# 上传取消与提交确认

网页上传使用每次尝试独立的 UUID 和 AbortController。等待项直接移出队列；传输中的取消首先中止 fetch，再向 Gateway 确认结果。Gateway 的回执与文档、版本、解析任务在同一事务提交，提交和取消共用用户行锁，跨实例也保持顺序。

- 取消先获得锁：保存 cancelled 回执，迟到的 multipart 请求被拒绝，不创建文件或任务。
- 提交先完成：返回 submitted、文档和任务编号；前端保留已提交状态，到任务中心取消解析，不声称上传已取消。
- 上传响应丢失：通过同一编号确认。确认也失败时显示“上传结果待确认”，用户可再次核实；不会自动重传或假报取消。
- 同编号重放返回原文档；失败后的主动重试使用新编号。编号属于当前用户和原资料库，不能跨库复用。

切换资料库不改变批次目标，上传继续交给原库。离开页面或切换用户不会主动中止已经发出的请求，结果写入原用户的本地队列；等待项取消，不再开始后续传输，不向新页面/账号发送旧回调。关闭浏览器或刷新可能丢失结果，重新进入后显示待确认；“核实上传状态”会确认提交或建立取消回执，阻止迟到请求。

Servlet multipart 由容器管理，完成/失败请求的临时文件由标准 multipart resolver 清理；业务文件复制使用 try-with-resources，复制中断会删除部分文件。创建文档或任务失败则回滚数据库并删除业务文件。服务已提交的文件保留给解析任务，不因客户端断开而删除。

回执只含编号、状态和关联，不含文件名或正文；随账号级联删除。已取消编号不可复用。部署代理必须允许独立的取消请求到达服务；代理或网络不可达时 UI 保留待确认状态。旧客户端不提供编号仍能上传，但无法使用这一取消确认协议。

回归包括真实 MySQL 的迟到上传、重放并发、旧事务快照、用户/资料库隔离、事务失败和部分文件清理；浏览器使用真实 localhost 服务限速大文件传输，验证中止请求、同批次继续、响应丢失后提交确认和窄屏布局。

本项验证：Java 116 项、前端单元 65 项、已有浏览器回归 58 项及真实上传桌面/移动 2 项全部通过；前端 Lint、生产构建与包大小检查通过。静态浏览器套件不运行需要完整服务的测试，这些测试通过显式真实环境单独执行。
