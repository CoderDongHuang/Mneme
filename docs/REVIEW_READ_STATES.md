# 复习卡与学习计划的独立读取

对应原审查 P3-03 的复习页异常状态及 P2-14 的渐进拆分；其他页面与整个审查仍需分别核验。

## 行为与边界

- 卡片和计划分别加载、失败、重试；尚未成功读取的指标显示 `—`。首次失败不能显示“今天的复习已就绪”“还没有计划”或空日历，只有成功空结果才能显示空状态。
- 读取失败保留缓存并提示可能过期；只重试失败部分，不重置其他数据、当前翻面或未提交计划草稿。
- `features/review/useReviewData.js` 负责两类列表的读取生命周期和响应代次，移除页面重复的初始化/刷新代码。新读取、卸载或评分成功后，旧响应不能覆盖当前结果。
- 创建计划以真实 POST 成功显示回执；后续列表刷新失败分别提示，不改成“创建失败”或重发创建。写入失败保留草稿，输入和操作锁防止提交期间修改或双击重复写入。
- 评分失败保留翻面与卡片，用户可以再次点击具体评分；不提供实际只会重新读取的假“评分重试”。成功评分直接使用服务端返回的到期时间和次数，旧读取不能将卡片恢复为未评分。
- 翻面绑定卡片 ID，切换到另一张卡不会自动暴露其答案。保留到期时钟，未来卡片到期后无需刷新即可复习。

## 部署与回退

只涉及前端和回归入口，无数据库迁移或 API 修改。保留旧容器、精确配置和匹配数据库快照后替换前端；失败恢复旧前端镜像与配置，无需回退数据库。评分本身沿用现有服务端语义，不新增网络失败后的自动重放或声称恰好一次交付。
