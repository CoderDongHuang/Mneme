## 长期记忆与版本的删除围栏

对应源码审查 P1-05 的跨存储清理、异常传播、独立读回，以及 MN-006 的迟到写入防复活。本项覆盖 Qdrant 长期记忆及 SQLite/MySQL 版本记录；短期/工作记忆、Redis 和内存缓存仍按后续独立项处理，不能据此关闭整个审查。

### 存储协议

复用持久 generation 用户锁及账号 tombstone。新增、编辑、恢复、冻结、重要性、主题和元数据更新在实际发布前检查账号状态；账号删除提交 tombstone 后，迟到写入与版本快照被拒绝。查找记忆的首次读取只用于发现所有者，锁内重新读取当前内容并检查所有者，避免并发操作用旧元数据覆盖新修改。

Embedding 调用在用户锁外完成，删除不等待供应商返回；返回后重新取得锁并检查账号状态，显式传入向量发布，不能在 Qdrant 内隐式重复调用供应商。纯元数据修改不重新计算向量。无法撤回已经发送给供应商的请求，也不承诺清除供应商侧数据。

更新、删除及历史恢复的“修改前版本”与存储更新位于同一用户锁范围，恢复先重新读取实际当前版本。恢复输入中的 id/content 不进入元数据；读取以真实文档和主键为准，避免元数据覆盖。Qdrant 和版本数据库不是跨库 ACID：版本已保存而 Qdrant 写入失败时可能多出一次有效的修改前快照；不自动重放非幂等业务，也不把这种情况当成已完成更新。

版本号的 MAX+INSERT 在 SQLite BEGIN IMMEDIATE 内分配。MySQL 命名锁在显式 commit 后释放；失败先 rollback 再释放，避免前一事务提交前下一实例计算相同版本号。公开快照与版本删除同样使用用户锁，内部快照仅供已持锁的存储操作调用，避免嵌套锁。

账号删除后不再创建删除快照；普通单条删除/清空不写账号 tombstone，仍保留可恢复版本，允许后续正常新增。Qdrant 删除后独立读回主键/用户数量，版本删除后独立 COUNT；读错和静默删除残留必须传播，供原后台任务重试，不能把异常当零。

### 验收

单元测试用真实本地 Qdrant 和 SQLite，暂停供应商结果验证新增、更新、恢复期间账号删除不会复活；覆盖写入中删除等待、并发字段保留、恢复前最新快照、32 个并发版本、删除静默残留、计数错误、恢复重试和另一用户隔离。MySQL 合约测试明确检查 commit/rollback 与 RELEASE_LOCK 顺序。

`python scripts/check_memory_deletion_fence.py selftest` 在实际部署中使用当前配置的 Qdrant 与 Embedding，分别以 SQLite 和 `AUXILIARY_STORE_BACKEND=mysql` 执行。只在独立脚本进程暂停已返回的供应商结果，服务源码与服务进程不打补丁。合成身份有明确 QA 前缀，finally 清除向量、版本与合成 manifest；不切换离线向量污染现有索引。

`memory-fence-real.spec.js` 在实际 localhost 桌面与手机注册三个隔离账号，写入真实长期记忆，运行迟到新增/恢复与并发版本，检查第三账号的页面、实际内容和全部 35 份版本仍完整。最后通过正式 DELETE 接口删除账号，等待持久 tombstone 及两存储零残留，再以新进程重放迟到修改核对。既有记忆编辑/历史恢复、会话清理及 Trace/隐私围栏一起回归。没有使用虚构响应替代本项存储结果；自动 trace/录像关闭，仅保存安全视口截图。脚本双存储和真实页面回归加入完整栈 CI。最终结果及独立读回见整改记录。

### 部署与回退

无新依赖、配置或迁移。SQLite 使用同一主机的共享文件；多副本必须全部采用共享 MySQL 用户锁及版本库，并使用一致的 Embedding profile，不能混用不共享的 SQLite 围栏。索引 profile 不匹配仍拒绝写入，不自动修改非空索引。

升级先停全部应用写入者，保存匹配 SQL 和 Agent 数据快照，保留旧镜像/容器及配置，然后切换 Agent。必须停止旧消费者，避免旧代码绕过围栏。回退同样先停全部写入者；跨批次恢复必须使用匹配的数据库、Agent 数据及镜像，不能仅恢复旧 SQL 或让旧工作器继续处理已删除账号。持久 tombstone 不能随意删掉。本项仅保证逻辑清理与拒绝迟到发布，不承诺 SQLite WAL、磁盘空闲页或历史备份的物理不可恢复清除；这些留存策略属于 P2-12。

## 记忆缓存删除围栏与共享失效

对应源码审查 P1-05 的跨存储清理、失败传播和独立读回，及 MN-006 的迟到写入防复活。本项覆盖长期记忆进程缓存及旧 Redis 版本键，不关闭短期/工作记忆、会话消息、P2-12 留存策略或整份审查。

### 协议与边界

共享缓存版本复用现有 generation 用户持久状态的 `memory_cache_revision`，不新增数据库表或依赖。读失败或非法版本必须报错，不降级到进程内版本。每次缓存命中也取得用户锁，检查账号 tombstone 和共享版本；读取供应商/向量库在锁外，发布时重新检查版本，版本改变则重新查询，最多三次，持续变更明确提示重试。缓存存入和返回均深拷贝，调用方修改返回值不会污染其他请求。

账号 tombstone 后，缓存读取和发布均拒绝并清除该实例本地缓存。清理不再创建 Redis 版本键；只删除旧 `mneme:memory-revision:{user}` 并独立 EXISTS 确认，静默删除残留、Redis 不可用及读错必须失败，让原删除任务重试。共享失效失败也在 finally 清理当前本地缓存。另一账号的缓存和旧键保持隔离。

无法远程立即擦除其他进程堆内存；其他实例下次访问时检查持久 tombstone 并拒绝返回旧数据。本项保证已完成失效后的旧查询不能标记为新版本，不把向量写入与随后失效宣称为跨库 ACID。存储写成功而共享失效失败时，调用方收到失败，需按真实存储核实；不自动重放非幂等写入。

### 验收

单元测试覆盖热缓存拒读、实际查询暂停期间删除、跨实例共享版本、并发更新重查、持续变更上限、深拷贝、损坏状态及历史键清理失败后重试。`python scripts/check_memory_cache_fence.py selftest` 在实际部署中分别以 SQLite/MySQL 执行，用实际 Qdrant 和当前 Embedding 配置；暂停独立脚本进程的真实存储读取结果，不替换服务进程，不修改现有向量 profile。finally 清理合成账号数据。

`memory-cache-fence-real.spec.js` 在实际 localhost 桌面和手机注册隔离账号，运行竞态，核对另一账号更新后的实际正文、页面及详情；最后通过正式 DELETE 删除账号，等待持久 tombstone、向量零残留及历史 Redis 键归零，再用新进程拒绝迟到发布。自动 Trace 和录像关闭，仅保存安全视口截图；既有记忆编辑、历史恢复及会话清理同时回归。双后端脚本及真实页面回归加入完整栈 CI。最终结果见整改记录。

### 部署与回退

升级后运行 `python scripts/cleanup_deleted_memory_revisions.py` 清理旧版本在账号删除后遗留的 Redis 版本键；使用与服务一致的 `AUXILIARY_STORE_BACKEND`。历史上若曾使用两种持久后端，分别核验并运行。扫描只处理存在持久 tombstone 的准确用户键，活账号和其他键保持不变，状态读取失败立即停止，删除后独立读回，再扫描确认；安全幂等重跑。仅 Redis 返回可信完整扫描时才能据此确认扫描范围，不宣称防御失真的后端协议。

没有新配置、迁移或依赖。SQLite 用于单主机共享文件，多副本必须一致使用共享 MySQL。升级先停止全部应用写入者，保存匹配的 SQL、Agent 数据和旧镜像/容器配置，再切换；旧版本工作器必须停止，否则仍可绕过围栏。回退也先停全部写入者，跨批次恢复须使用匹配数据和镜像，保留 tombstone，不让旧消费者处理已删除账号。逻辑清理不等于 SQLite WAL、磁盘空闲页或历史备份的物理不可恢复擦除。

## 会话清单的原子写入与账号删除围栏

对应原审查 P1-05 / MN-006 的失败传播、清理清单与删除后不可复活。本项只关闭 JSON 会话元数据边界；不代表 Redis、短期/工作记忆、长期记忆及版本的全部迟到写入已经隔离。

所有修改和 TTL 裁剪从读取到发布完整持有既有用户 generation 数据库锁。两个 Store 实例的并发注册、计数不再相互覆盖；删除先持久 tombstone，等待已有写入结束，后续注册、标题、计数、删除单会话及兼容保存均拒绝。读取已删除账号返回空且不创建文件，清理接口仍可严格枚举旧清单并执行幂等删除。

仅文件不存在视为空。损坏 JSON、错误结构和 I/O 故障向上传播，不能把清理范围当空或覆盖。写入使用同目录临时文件、flush/fsync 和原子 replace；序列化、fsync 或 replace 失败保留旧字节并清临时文件，失败可重试。删除后独立检查路径不存在。原有文件名、JSON 格式和 TTL 不变。

真实八线程测试还发现 MySQL `INSERT IGNORE` 先取得重复键共享锁，再 `SELECT FOR UPDATE` 升级会发生死锁。初始化改为不覆盖任何状态的 no-op upsert，直接取得排他行锁；保留 tombstone，禁止通过重放业务体来掩盖冲突。没有新依赖、配置或数据库迁移。

### 升级与边界

文件仍是单主机缓存；多实例须同时共享会话目录与 MySQL 围栏，数据库锁不能复制本地文件。本项保证正常运行中的原子发布，不承诺目录 fsync 或断电持久性；进程被杀遗留的临时文件及物理留存仍属 P2-12。账号 tombstone 不因删文件而移除。普通删会话不等于删除账号，后续正常会话仍可创建。

实际部署先停 frontend、Gateway、Agent 全部应用写入者，保留匹配 SQL、Agent `/app/data` 目录、配置及旧容器，再切镜像。依赖锁未改，本地基于锁一致的已验收镜像复制源码，正式 CI 使用标准全量构建。回退须停全部新工作器并恢复匹配镜像和数据点；旧代码不理解围栏，不支持混跑。证据见整改记录。

## 单会话删除的持久任务与跨服务围栏

对应原审查 P1-05 / MN-006 的跨存储清理核验，以及 P3-03 的“请求受理不等于完成”。本项处理单个对话，不以账号删除替代单会话清理。

### 行为与失败恢复

Gateway 在短事务内锁定活动账号及归属会话，将会话隔离为 `delete_pending`，停止正在生成的助手消息，并提交独立 `session_delete` 任务。列表、消息读写、重命名、回答重试及候选记忆保存拒绝被隔离会话。DELETE 返回 `accepted`、`task_id`、`status`；重复请求返回同一持久回执，完成后仍可查询。前端防止重复提交，只在回执可核验后移除列表条目，并提供任务中心入口。

工作器在数据库事务外调用内部 Agent；Agent 先独立提交永久会话 tombstone，再清短期/工作记忆、Redis 消息和 manifest。Redis 独立计数及 manifest 重新读取均通过后才返回带精确会话 ID 的删除回执。清理失败不撤销围栏、不丢弃清理依据。所有会话缓存读写和摘要发布检查共享持久状态；迟到消息、冷进程旧历史和在途摘要不能重新发布。其他账号、其他会话保持可用。

Gateway 严格核验 Agent 回执，再在当前任务租约事务中删除此会话的候选任务、待确认记忆、消息和 canonical 会话，并独立读回计数；SQL 异常全事务回滚，过期 owner 不得完成任务。失败保留隔离状态和同一任务，可在服务恢复后从任务中心重试，不能取消清理并重新开放已开始删除的会话。外部错误正文不写入任务诊断。

### 升级与回退

V32 为 `chat_session` 增加 `deletion_status`，既有会话默认为 active。停止全部旧应用写入者，备份匹配 SQL、Agent data、旧镜像与容器配置，再整体升级三服务。不能同时运行绕过隔离状态的旧 Gateway/Agent。SQLite 仅单主机，多副本需共享 MySQL 和会话目录。

迁移后回退必须恢复匹配 SQL、Agent data 和旧镜像，不能仅将镜像降级。升级后新写入数据应先另行保存，不能盲目覆盖。部署若在迁移后失败，应停写并使用匹配备份恢复或修复新版后验证；本项不代替全项目升级/回退演练。

## Trace 与隐私策略的账号删除围栏

对应原审查 P1-05 / MN-006 的跨存储删除、异常传播、独立残留检查与重试要求。本项仅处理 Trace 和隐私策略；知识索引和反思已有独立协议，长期记忆、会话及缓存迟到写入仍需各自验收，不把整个删除 Saga 提前标记完成。

### 行为与边界

复用已有持久用户 generation 行。Trace 插入和隐私策略保存只在实际存储阶段持有该用户数据库锁；账号删除先永久 tombstone，再清理。已进入锁的写入先结束，删除后才到达的写入被拒绝。数据库读取失败直接失败，不降级为允许处理。已删除用户即使策略行已移除，也不能恢复默认云授权；外部模型授权检查保留 StaleGeneration 契约。

删除提交后独立 COUNT；静默 DELETE 或 COUNT 故障向上抛出，让删除任务保持可重试。普通“删除我的 Trace”不删除账号、不设置 tombstone，之后正常交互仍可记录新 Trace。账号 tombstone 保留，不因清理策略行或重启而消失。

不能撤回已经发送给模型供应商的请求，不在供应商调用期间持数据库锁。SQLite 为单主机模式；多实例须使用既有共享 MySQL 配置。这里保证逻辑不可复活与可验证清理，不承诺备份、WAL 或底层介质物理擦除。没有新增依赖、配置或迁移。


<a id="session-memory-account-fence"></a>

## 会话缓存账号隔离、共享版本与删除围栏

对应原审查 P1-05 / MN-006 的跨存储删除清单、失败传播、独立残留读回与恢复重试。本项覆盖短期记忆、工作记忆和 Redis 会话消息的账号边界；不把单会话删除 Saga、历史留存或物理擦除计为完成。

### 行为

实际运行链路显式传递用户 ID，内存以用户和会话组成键，输入输出消息深拷贝。会话详情和删除接口要求提供用户 ID；这些仍是受内部凭证保护的 Agent 接口，用户归属授权由 Gateway 执行，传入 ID 本身不是鉴权。

短同步事务复用持久 generation 用户锁，读取/写入先检查账号 tombstone；数据库不可读时不能返回本地旧历史。模型调用在事务和内存锁外执行，摘要返回后重新检查版本和历史，迟到结果丢弃，已删账号拒绝发布。线程局部重入只允许同一账号，不能用复制的异步上下文绕过数据库锁；作用域内不得 await 或执行模型调用。

Redis 新消息键使用用户 SHA256 和会话 SHA256 命名空间，载荷带随机版本；版本保存在既有持久用户状态中。不同实例在锁内追加，版本改变时重新读取 Redis；即使 Redis 写失败也推进版本，使其他工作器不能误用旧载荷。随机令牌防止 Redis 写入后数据库回滚时，下次提交重复使用版本而意外恢复孤儿消息。Redis 故障仍可在当前实例保留内存消息，但不宣称这种降级是跨实例可靠持久化。

旧裸会话键仅在新版本尚未建立、严格读取的 manifest 明确记录同一用户时允许恢复。运行时先注册 manifest 再读取会话；损坏或读取失败不能授予归属。升级后的正常写入使用新键，旧键随 TTL 或清理删除，不复制到其他账号。

正式账号删除永久停止写入后，除了 Gateway 的权威会话 ID 批次，还扫描该用户新键前缀清理缺失元数据的孤儿；独立 SCAN/EXISTS 核对，不把静默删除或读取异常当成功。失败保留 manifest 供任务重试。清本实例短期、工作记忆；其他实例每次访问先检查持久 tombstone，拒绝返回旧消息。

### 升级与回退

无依赖、配置或数据库结构迁移，但 Redis 载荷及用户状态增加版本字段。停止全部旧应用写入者，保存匹配 SQL、Agent 数据、旧镜像及容器配置后整体升级，不能混用旧写入者。回退时使用匹配数据和镜像；旧版本无法理解新键，不能承诺只回退镜像仍保留升级后对话。SQLite 为单主机，共享实例使用 MySQL 并共享会话目录。

工作记忆仍为实例内窗口，不提供跨进程消息复制。用户状态版本记录的留存和历史备份/WAL/进程堆内存物理擦除属于后续存储生命周期治理。Java 单会话删除尚需跨服务可靠清理，本项账号围栏不能代替该流程；不宣称整份审查或 MN-006 全部完成。


<a id="session-cleanup-readback"></a>

## 账号删除：会话清单及读回

对应原审查 P1-05 / MN-006 的 Redis、文件清理与失败重试子项。

Gateway 在 `session_cleanup` 阶段按用户从 MySQL `chat_session` 读取权威清单，以 ID 游标每批最多 1000 个发送到内部 Agent。MySQL 会话直到后续账号删除才级联移除；任一批失败或回执不可验证都保留本阶段及会话行，下一次从完整清单重试。不调用会自动裁剪 TTL 的界面列表来确定删除范围。

内部 `POST /api/v1/admin/user/{user_id}/session-cache` 接受 1–1000 个 ASCII 数字 ID，逐一清理短期和工作记忆、删除 Redis key，并以独立 `EXISTS` 读回。Gateway 严格验证 `status=verified`、整数 `checked_sessions=批次大小`、整数 `redis_sessions=0`；缺失值、布尔、字符串或浮点数都不当作成功。此接口依赖现有内部服务认证，只接受受信 Gateway 从用户归属查询得到的 ID；不对公网提供任意缓存清理能力。

随后 Agent 直接读取未裁剪的 JSON 清单，兼顾历史本地条目。文件不存在表示没有可选元数据；损坏、结构错误、权限拒绝则失败，不能当成空结果。所有缓存、Trace 和隐私清理及 Redis 最终读回成功后才移除清单，删除后检查文件路径确实不存在。这样失败后仍有本地重试范围。重复删除幂等，其他用户清单与缓存保持。

### 升级与边界

Gateway 新增内部调用依赖新版 Agent；停写并备份匹配数据库、持久目录和旧镜像，一起升级，不混跑旧新版本。接口不引入新数据库迁移；回滚仍须按部署手册停写恢复匹配快照和旧容器，不能仅换镜像后继续写。

这不是完整账号擦除协议：在途模型/反思写入的防复活、跨实例进程缓存清理、其他存储的最终账号级核验及 SQLite WAL/备份的物理保留仍需后续独立完成。该项不证明物理不可恢复清除，不提前关闭整个 MN-006。


<a id="reflection-account-cleanup"></a>

## 账号删除：反思数据清理与在途任务拒绝

对应审查 P1-05 / MN-006 的 Redis 反思子边界，并按 P2-01 验证迟到执行不能提交。本项不代表全部会话、记忆、缓存、轨迹写入路径已经具备删除围栏，也不关闭完整 MN-006。

### 持久拒绝与并发顺序

复用 `knowledge_index_state` 的用户级 `deleted` 状态，不新增表或迁移。计数投递、任务排队、领取、旧协议迁移和最终完成均在同一用户的持久事务锁内检查该状态，再变更 Redis。SQLite 使用 `BEGIN IMMEDIATE`，只适合单主机；多实例必须共用 MySQL 辅助存储并使用 `SELECT FOR UPDATE`，不能让各实例使用各自 SQLite。

删除先独立提交用户 tombstone。已经持锁的写入会先排空，后到的写入一律拒绝；即使 Redis 随后报错，持久拒绝也不回滚。接下来不长期持有数据库锁，分页清理 Redis。数据库不可用时不能绕过检查，也不回退本地；消费线程记录异常类型并保留待处理任务，稍后继续消费，不输出异常正文。

模型调用不持数据库事务。已经发给供应商的请求无法由此取消；目前反思仅只读并返回分析，失权或已删除用户不能完成队列提交。未来若反思新增写入副作用，必须在对应存储层延伸围栏，不能只依赖完成时检查。续约只延长已存在且 owner 匹配的租约，不创建已清理的键。

### 清理范围与成功条件

1. 删除准确用户的计数、任务预约、执行租约与租约状态。
2. 用 SCAN 分页删除投递标记，每批 200；转义旧导入用户的 Redis glob 字符，严格校验 64 位摘要后缀，避免前缀用户误删。
3. 捕获共享 Stream 的扫描上限，以 XRANGE 每批 200 扫描，准确匹配 `user_id`；清除新旧协议、已投递及未投递条目。Lua 内先 XACK 再 XDEL，不删除共享 Stream 或消费者组。旧无组的 NOGROUP 可以兼容，其他异常传播。
4. 通过独立 EXISTS、SCAN 与 XRANGE 读回确认零键、零条目。静默删除无效、读取异常或残留均失败，不返回成功。

`DELETE /api/v1/admin/user/{user_id}` 先完成上述步骤，再清理会话与轨迹等原有数据。反思清理失败保留会话清理清单，Gateway 删除 Saga 不能因此完成，可恢复后重试；成功响应增加 `reflection: {keys: 0, queue_entries: 0}`。重复删除幂等。

这里只承诺应用层逻辑清理与新写入拒绝；Redis AOF、数据库备份和已交给供应商的内容不等于物理不可恢复擦除。持久 tombstone 不含正文，必须保留以拒绝迟到任务；不能用清空该行的方法“整理”真实已删除账号。

### 验收与升级

单元回归覆盖在途写入排空、删除先提交、数据库故障拒绝、Redis 故障重试及会话清单保留。`scripts/check_reflection_cleanup.py` 使用独立 QA Stream，实际验证跨页的 450 条混合租户队列、410 个额外标记、pending 清除、模型暂停时删除、旧 owner 拒绝、静默删除/读取异常、前缀与 glob 用户隔离；分别在 SQLite 与共享 MySQL 运行。脚本结束只删除保留的合成 QA 身份行，严格限定格式，绝不清理真实用户 tombstone。

隔离 Redis 验证有/无密码、AOF fsync、SIGKILL、重启与 pending 接管，并重新运行所有权、投递去重及清理检查。真实 `session-cleanup-real.spec.js` 在桌面/手机分别注册两个账号，建立实际会话、反思键与两条 pending 任务；删除目标后直接读回 Redis、MySQL 与持久状态，再在新进程重放所有反思写入入口。另一个账号的网页会话、键和队列均保留，最后删除两账号并再次读回。实际结果与 PR 合并记录见 [整改记录](CODE_REVIEW_REMEDIATION_20261031.md)。

升级前停止所有旧 Gateway、Agent 和反思工作器，保留匹配 SQL、Redis、数据卷、配置及镜像快照。旧工作器不识别持久拒绝，不能混跑。回退需停止全部写入者并恢复匹配快照，不能仅换回旧镜像；还原快照可能恢复当时尚未删除的账号或任务，必须复核删除清单。当前无新增依赖、配置或迁移。


<a id="profile-mutation-isolation"></a>

## 个人资料写入与账号删除的并发约束

头像上传、修改密码、邮箱修改、密码重置及账号删除在提交用户状态时使用同一个 MySQL 用户行锁。锁内读取当前行，不能把请求开始时的整个 User 快照重新写回数据库。各操作只更新自己负责的字段。

### 头像

文件复制期间不持有用户行锁。复制完成后锁定并确认用户仍为 active，再更新 avatar_path；如果账号删除先获得锁，上传回滚，不得把 deleting 或 deletion_failed 恢复为 active。

输入流通过 try-with-resources 关闭。事务回滚（包括复制失败、数据库拒绝更新和删除竞争）清理新文件，事务提交后才清理旧文件。两个并发上传按用户行锁顺序提交，后提交者保留自己的文件并清理前一个已提交的头像。文件清理范围限制在配置的头像根目录内。

### 密码与删除

修改密码在锁内验证最新密码 hash，只更新 password_hash；全部登录会话撤销与密码修改在同一事务中。撤销失败时密码也回滚；同一旧密码的并发修改只有一个可以成功。已进入删除流程的用户不能继续读取资料、上传头像或修改密码。

删除入队只更新 status；后台失败回写也只更新删除状态，且仅接受已有 deleting/deletion_failed 的行。不会覆盖其他字段或复活账号。

### 保证范围

MySQL 事务与本地文件系统不构成原子事务。此处保证正常异常/事务回滚的清理，以及提交后旧头像清理。进程强制退出、磁盘不可写或 afterCommit 文件删除失败仍可能留下孤儿文件；清理失败仅记录异常类型，不打印用户路径。孤儿文件和备份保留属于审查 P2-12，不能据此宣称物理不可恢复删除。
