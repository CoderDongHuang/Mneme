## 学习记忆读取、保存与版本恢复

对应原审查 P3-03（记忆页面）及 P2-14（版本历史边界）。本项不代表所有页面异常状态或整个渐进拆分计划完成。

### 页面行为

- 记忆列表和待确认列表分别记录首次加载、成功、失败。未取得成功结果的指标显示 `—`；只有成功返回空结果才能显示空状态。
- 部分读取失败保留另一部分成功结果。刷新失败保留已有数据和编辑草稿，并明确提示记录可能过期；用户可以重试。
- 保存、确认等写入回执与后续读取错误分别展示。候选确认成功先移除已消费的候选，不能因刷新失败重新显示为可确认。
- 新读取及写入会使旧列表读取失效。写入期间锁定条目选择，迟到读取不能覆盖已保存结果。
- 版本历史由 `features/memory/MemoryVersions.jsx` 独立负责读取、重试和失效保护。切换条目、卸载或版本刷新后的旧响应不能污染当前选择。
- 版本读取失败保留缓存并提示过期，禁用恢复；不显示假“零版本”或“暂无历史”。保存成功后的版本刷新失败不会改成“保存失败”。
- 恢复成功以服务端返回的记录更新正文、主题、标签和状态，再重新读取版本。
- 窄屏搜索独占一行，图标不压缩、输入不换行；真实浏览器验证移动端输入可用宽度至少 250px，并实际输入、清空搜索词。

### 实际传输故障

真实站点回归发现 Gateway 的默认 `SimpleClientHttpRequestFactory` 使用 HttpURLConnection，不能发送记忆编辑所需的 PATCH，导致实际保存返回 500。主要业务客户端改用 JDK HttpClient，明确固定 HTTP/1.1，禁止跟随重定向，连接超时 30 秒、读取超时 120 秒。原有个人模型、内部服务认证及 Trace 拦截器保留；监控和灾备的专用客户端不变。

真实 HTTP 单元回归验证 PATCH、中文正文与标签、HTTP/1.1、无 h2c Upgrade，以及内部凭据不发送给其他 origin。真实浏览器回归再通过实际 Gateway/Agent/数据库验证保存和恢复，不 mock 写入。

重复回归还发现内部服务限流 429 被通用异常处理误报为 500。Gateway 现在返回统一的 429 与受限的 `Retry-After` 秒数，不转发内部响应正文或其他头；无效重试时间回退到 1 秒。测试只对真实 429 按该时间有界重试，500 不重试，也不通过调高生产限流掩盖错误。

账号删除汇总验收进一步发现，Agent 原先按 Gateway IP 共用一个令牌桶，删除读回与状态轮询耗尽预算后，正常聊天也被拒绝。现在同一来源 IP 固定分为推理（同步聊天、流式聊天、测验）、普通交互与清理核验三类预算，各自沿用 `INTERNAL_RATE_LIMIT_BURST`（默认 60）及 `INTERNAL_RATE_LIMIT_PER_SECOND`（默认 1）；不是逐用户配额，多个 Gateway/Agent 实例也不是分布式共享预算。鉴权仍在限流之前执行，任意路径、用户头及新用户不能创建额外预算。429 的 `Retry-After` 按实际缺额与补充速率向上取整。

`answer-terminal-real.spec.js` 设置 `MNEME_RATE_LIMIT_QA=true` 后，先通过真实 Gateway 隐私读取耗尽内部服务预算，再验证聊天完成时立即断流、数据库答案与引用、重复请求及刷新。仅在隔离验收环境启用压力步骤；普通真实回归保留全部落库断言。2026-11-04 localhost 桌面、手机两项通过；中间件、鉴权及生命周期定向测试 26 项通过。

### 升级与回退

本项无数据库迁移，不改变公开 API。部署前保留旧容器、镜像标识及匹配数据库快照；部署网关和前端，确认健康后执行真实回归。失败时恢复原容器配置和镜像；若恢复数据库快照，必须先停止写入，不能覆盖部署后仍需保留的业务数据。

## 运维与审计独立读取状态

对应 2026-10-30 审查 P3-03，并按 P2-14 拆出一个业务边界：`features/operations/useOperationsData`。不改变 API、管理员授权或页面主题。

### 状态与权限

- 运维快照与操作审计各自串行轮询、加载、报错和重试；慢快照不会阻塞已返回的审计。初次失败不显示“暂无记录”。只有成功返回的空数组才是空记录。
- 刷新失败保留上次成功数据，并明确提示可能过期。重试审计不重发快照请求；全局刷新同时读取两者。
- 审计响应不是数组时报错。快照允许部分字段缺失，缺失表格显示不可用；任务查询状态不是 `available` 时不展示部分任务结果。监控不可用时不把告警解释为零条。
- 缺失健康状态显示 `— / 3`，缺失邮件配置显示不可用，而非推断为未配置。可见的依赖探针仍明确说明不代表端到端业务成功。
- 凭证仅在当前挂载的组件内使用。锁定卸载两个读取器，取消请求、清空缓存与凭证；旧请求即使迟到也不能污染新凭证的数据。凭证不写浏览器存储。
- 普通用户仍由真实 Gateway 拒绝；管理员还需有效的独立管理员凭证。前端的解锁按钮不是授权依据。

### 部署与范围

无迁移、新依赖或服务端业务更改。部署前停止全部应用写入者并保留匹配数据库快照、镜像和原容器。原本地 Gateway 的管理员凭证为空，首次真实测试停在配置检查；配置独立随机本地凭证后完整重跑通过，未降低生产授权规则。凭证和原配置保存在忽略的私有部署产物中，不提交仓库。

前端可恢复保留的原镜像；若恢复数据，必须匹配所有存储和部署配置，遵循 [自部署说明](SELF_HOSTING.md)。本项不关闭所有页面的 P3-03，也不将 P3-07 真实 SMTP、Redis、数据库权限、存储和备份密钥业务诊断标为完成。

## 隐私策略与审计记录的独立读取

对应原审查 P3-03 的隐私页异常状态及 P2-14 的单一业务边界拆分；其他页面、后台清理保留策略和整个拆分计划仍需逐项核验。

### 页面行为

- 隐私策略和审计记录分别显示加载、读取失败与重试。首次读取失败不能显示“暂无记录”，只有成功返回空列表才能显示。
- 策略服务不可用时仍可使用独立的导出和 Trace 删除操作。
- 审计记录迁至 `features/privacy/PrivacyOperations.jsx`，重试不重新读取或覆盖策略草稿、删除确认输入。
- 刷新失败保留已有审计记录并提示可能过期；卸载或新一轮读取后忽略迟到响应。
- 保存策略或删除 Trace 以实际写入结果显示成功回执。后续审计读取失败单独提示，不能误报写入失败、重复执行删除或丢失成功回执。
- 写入失败保留草稿并允许再次提交；操作锁防止双击重复写入。写入期间禁用策略与确认输入。

## 测验读取状态与草稿切换保护

对应审查 P3-03 的测验页读取异常和 P2-14 的渐进拆分；本项不代表全部页面或整个审查已完成。

- 测验列表和资料库独立加载与重试，未读取指标显示 `—`，只有成功空结果才显示空提示。资料库重试不清除创建主题。
- `features/quiz/QuizAttempts.jsx` 单独管理历史加载、重试和过期缓存，旧测验的迟到响应不能覆盖新测验。历史故障不会阻塞草稿读取或作答。
- 草稿读取失败有独立重试，不再永久显示“正在恢复”。保存失败保留当前答案并阻止切换测验或打开历史，重试真实保存成功后才能离开；保存中锁定编辑和其他选择。
- 提交沿用现有 request_id 幂等契约，同一答案失败重试复用编号；成功结果与历史刷新失败分别显示，重试历史不会重发提交。刷新后可重新打开真实历史。
- 生成失败保留资料库和主题，生成成功使用明确回执。新增提示同步提供英文翻译。

### 部署与边界

仅修改前端、测试与 CI，无 API/数据库迁移。部署保留旧容器、精确配置和匹配 SQL 快照；回退恢复旧前端即可，不回退业务数据。500ms 自动保存与卸载时尽力保存继续保留；关闭浏览器、断电或跳转其他路由时不保证未确认草稿已持久化。本次保护明确针对同页切换测验和打开历史，不声称离线持久化或所有网络写入恰好一次。

## 恢复演练：读取、提交与凭证隔离

对应审查 P3-03、P2-14，并沿用 P3-02/P3-04 的共享格式与反馈组件。本项只处理管理员 GitHub 隔离演练，不将整站执行器与个人恢复向导的所有状态提前关闭。

历史、报告、提交状态迁入 features/recovery/useRecoveryDrillData。历史首次加载与真正空列表分开；串行轮询与手动刷新合并，失败可独立重试，已加载历史在刷新失败时明确标记可能过期，不能把失败显示为无数据。历史与报告的可渲染字段校验失败会显示错误，不因畸形数组或对象导致页面崩溃。任务状态和附件大小使用共享 formatter，排队不显示为已完成。

锁定会卸载整个凭证作用域，包括整站子组件、历史、报告、确认语句与提交回执，取消读取和客户端提交等待。报告切换取消前一读取并校验最新请求身份；即使传输忽略取消，旧结果也不能覆盖新报告或新凭证作用域。凭证只存在内存，不保存到浏览器存储。历史读取出现 401/403 时不继续展示旧历史或报告。

提交使用同步锁，禁用确认输入以阻止重复提交，只在后端明确返回 accepted 后显示已提交；后续刷新失败不覆盖该回执。提交遇到网络错误表示结果未确认，提示先刷新核实，不自动重新 POST。客户端取消并不保证已经发出的 GitHub 调度被撤回；重新解锁后需读取历史确认，不能据锁定认定演练取消。完整演练的最终状态由 GitHub 历史、报告与附件决定。

## 复习卡与学习计划的独立读取

对应原审查 P3-03 的复习页异常状态及 P2-14 的渐进拆分；其他页面与整个审查仍需分别核验。

### 行为与边界

- 卡片和计划分别加载、失败、重试；尚未成功读取的指标显示 `—`。首次失败不能显示“今天的复习已就绪”“还没有计划”或空日历，只有成功空结果才能显示空状态。
- 读取失败保留缓存并提示可能过期；只重试失败部分，不重置其他数据、当前翻面或未提交计划草稿。
- `features/review/useReviewData.js` 负责两类列表的读取生命周期和响应代次，移除页面重复的初始化/刷新代码。新读取、卸载或评分成功后，旧响应不能覆盖当前结果。
- 创建计划以真实 POST 成功显示回执；后续列表刷新失败分别提示，不改成“创建失败”或重发创建。写入失败保留草稿，输入和操作锁防止提交期间修改或双击重复写入。
- 评分失败保留翻面与卡片，用户可以再次点击具体评分；不提供实际只会重新读取的假“评分重试”。成功评分直接使用服务端返回的到期时间和次数，旧读取不能将卡片恢复为未评分。
- 翻面绑定卡片 ID，切换到另一张卡不会自动暴露其答案。保留到期时钟，未来卡片到期后无需刷新即可复习。

### 部署与回退

只涉及前端和回归入口，无数据库迁移或 API 修改。保留旧容器、精确配置和匹配数据库快照后替换前端；失败恢复旧前端镜像与配置，无需回退数据库。评分本身沿用现有服务端语义，不新增网络失败后的自动重放或声称恰好一次交付。

## 整站恢复：读取、归档校验与接受回执

对应原审查 P3-03、P2-14，沿用 P3-02/P3-04 的共享状态、日期、大小和反馈组件。只拆整站执行器页面的数据边界；不改备份格式、执行器权限、恢复算法或既有 API，不将完整恢复演练或整份审查提前标记完成。

### 行为

首次读取、空历史与失败分开。历史串行轮询并合并手动刷新；刷新失败保留缓存，明确提示可能过期，同时暂停备份、校验和恢复。读取未成功、正在读取或有 queued/running 任务时不能提交。数组、可渲染字段和报告指标先校验，错误响应显示可重试失败，不导致渲染崩溃。后台状态与恢复阶段使用共享 formatter。

归档校验使用独立 AbortController 和最新请求身份。切换归档清除原校验，取消旧请求；即使旧请求忽略取消后迟到，也不能覆盖新选择。重新校验时先撤销原成功，失败不能保留“通过”。历史中的归档消失或大小改变同样撤销校验。恢复只提交当前选择的已验证摘要；宿主机仍在接收和执行前重新核对内容哈希，防止同名、同大小归档内容变化。

每个凭证对应独立挂载作用域。锁定或更换凭证会清空归档选择、预览、历史、对话框和回执，取消历史、校验、提交的客户端等待；迟到响应不能进入新作用域。历史 401/403 清空旧数据与校验。凭证只在内存，不进入 localStorage/sessionStorage。

提交在业务 hook 内以同步锁防重复，并在确认时重新检查历史和当前归档，已打开的危险确认框不能绕过后来发生的失败。接受响应必须是匹配当前操作的有效任务，显示“已接受”而非完成；后续刷新失败不覆盖回执。该任务出现在历史前阻止重复提交，之后仍按 queued/running 状态阻止并发任务。提交异常表示结果未确认，不自动重发；先成功刷新历史核实后才重新允许人工操作。客户端取消不能撤销已发给宿主机的任务，刷新或重新解锁后必须检查真实历史。

### 验收与边界

单元回归覆盖首次失败与重试、非法响应、串行刷新、缓存过期、归档竞态、失败撤销原成功、归档变更、已打开确认框、重复提交、接受后读取失败、未确认提交和权限撤销。全量前端测试、Lint、生产构建和原包大小门禁必须通过。

site-recovery-states-real.spec.js 在实际 localhost 桌面与手机注册隔离账号，真实验证普通用户和错误管理员凭证的 403，并检查管理员实际 GET。未配置宿主机执行器时必须显示真实 400 错误，不能伪装空历史。随后浏览器历史 GET 和只读归档校验 POST 使用明确夹具验证故障、过期、响应归属与锁定；没有调用真实归档校验或创建整站任务，不宣称已完成生产恢复演练。测试阻止所有未明确夹具化的恢复类非 GET 请求，必须计数为零。QA 账号通过正式删除接口清理，凭证和自动 Trace/录像均不落盘；仅保存明确安全的视口截图。测试加入完整栈 CI；最终本地证据和 PR 结果记入整改记录。

实际执行器 GET 依据 Gateway 当前环境分别核对：未配置 URL 或有效凭证时必须返回准确的未配置 400；已配置但执行器未启动、超时或拒绝时必须返回对应的明确错误并呈现失败状态；成功时必须返回有效历史。CI 配置了 URL/凭证但此阶段尚未启动宿主机执行器，不能将该状态误判为“未配置”。不接受其他任意 400，也不为覆盖配置分支启动真实恢复任务。

无新依赖、配置或数据库迁移。部署保留前端镜像、配置与匹配的停写快照；本地先停全部应用写入者导出 SQL，保留旧容器再切换前端。仅本项前端可切回保留镜像；跨其他批次变更回退必须按相应文档恢复匹配点，不能只恢复旧 SQL。


<a id="personal-recovery-request-ownership"></a>

## 个人恢复：校验归属、未知结果与下载生命周期

对应原审查 P3-03、P2-14，并沿用 P3-02/P3-04 的共享日期、大小、反馈和状态组件。本项只拆个人恢复请求边界，不修改归档格式、服务端恢复算法或现有 API。无新增依赖、配置、CSS 或数据库迁移。

### 行为

请求迁入独立 hook，删除页面原请求实现。重新校验先撤销旧成功；失败不能保留“通过”。改变文件或范围取消旧校验，响应还必须属于当前选择和请求，即使传输忽略取消也不能覆盖新预览。校验响应检查范围、大小、摘要、兼容性、恢复模式、覆盖数量和可渲染字段，非法响应明确失败。恢复提交重新检查当前预览、步骤及确认语句，同步锁阻止重复 POST。

成功导入显示关系数据提交和文件恢复数量，索引仍需等待任务完成后验证，不冒充全部检索已就绪。提交失败或非法回执视为结果未确认，撤销旧校验并阻止当前挂载中的重复提交；用户须到资料库、会话或学习页核实后，明确点击“已核实结果，重新选择归档”。重置同时清除真实文件输入。

该限制是当前挂载中的客户端保护，不是服务端持久幂等。离页、刷新或客户端取消不能撤销服务端已接受的导入；重新进入前仍须核实真实数据，重复导入可能产生副本。后续跨请求持久去重必须独立设计，不可把本项描述为恰好一次恢复。

离页取消校验、提交和下载等待，拒绝迟到更新；下载在读取响应体后再次检查取消，即使响应体忽略取消也不能再创建下载链接。账号 ID 改变重新挂载整个恢复视图，个人预览、下载记录和管理员数据不会留给下一账号。切换页面标签仍保留当前个人向导，不把标签切换误认为服务端操作撤销。

## 任务中心：独立读取与提交回执

对应 P3-03、P2-14，复用 PageHeader、FeedbackBlock、StatusPill，不增加 CSS 或品牌色。任务与阶段日志迁入 features/tasks/useTaskCenter，各自串行轮询、取消和重试；慢日志不阻塞任务，慢任务不阻塞活动。首次加载、真实空结果与失败分开，非法列表及可渲染字段作为读取失败处理。刷新失败保留原快照并明确提示可能过期，阶段失败不把缓存阶段显示成最新阶段。任务快照过期或正在读取时禁用重试、取消和诊断复制；仅日志失败不阻止基于当前任务的操作。

重试/取消有同步锁并在提交前核对当前任务状态，成功回执必须匹配任务编号及允许的状态。提交已接受不代表后台完成；后续读取失败不覆盖接受回执。操作成功使原先在途的任务读取失效，并排队一次新读取，旧响应不能恢复已过期的状态。读取故障的重试只 GET，不重新 POST。未知或非法提交结果显示未确认，先重新读取核实；不自动重发写入。离页取消 HTTP 等待、轮询与通知，忽略迟到结果，但不能据此认定服务器已撤销操作。

详情打开时读取反馈放在详情内，保证手机模态弹窗中可见且能操作；关闭后回到外层反馈，避免重复区域。

新增真实测试 task-center-states-real.spec.js：隔离账号通过真实注册/删除接口创建清理，SQL 仅插入该账号的安全失败任务与阶段；浏览器读取故障明确注入断网，成功读取和重试 POST 均由实际 Gateway/MySQL/worker 处理。隔离通知 SSE，避免 worker 通知影响手动 GET 计数；通知刷新由单元测试单独覆盖。检查独立重试、提交后断网、回执保留、旧状态不可写、一次 POST 和 SQL 中 worker 最终 completed 状态。验收后账号与任务清零，桌面和手机截图仅保留到视觉核对结束。测试加入完整栈 CI。

无数据库迁移、新依赖或配置变更。前端部署沿用原环境、网络、端口；既有匹配 SQL/Agent/Redis 快照和旧容器组保留，不新增全量副本。仅此页面变更可切回原前端镜像，跨批次回退仍需匹配其他服务与数据。主项保持未完成直到完整矩阵验收。

## 知识库：读取归属、过期快照与提交回执

对应 P3-03、P2-14。资料库、文档和活动的读取边界迁入 features/knowledge/useKnowledgeReads，删除页面原读取与静默失败实现；复用串行轮询及 FeedbackBlock，不增加依赖、CSS 或数据库迁移。

刷新进行中继续基于已验证快照显示筛选结果或无匹配提示，同时显示读取中且禁止依赖列表的写入。桌面预览在文档 ID、版本或重试改变的同次渲染即隐藏旧内容；文档变空不再访问旧预览，迟到预览不能污染新选择。

三个区域各自读取、报错和重试。首次失败不显示空状态，合法空结果与筛选无匹配区分；刷新失败保留旧快照并提示可能过期，依赖当前列表的提交在读取或失败时禁用。活动错误不阻断文档读取与操作。通知触发串行合并刷新，卸载取消 HTTP、计时与通知；账号变化重新挂载，切库立即隐藏旧文档并取消旧请求。迟到读取与旧库提交回调不能改变新库数据。

本地提交回执使原在途 GET 失效，排队一次新读取，避免旧状态覆盖已提交状态。删除、解析显示任务已提交，最终结果仍以任务中心及后续真实列表为准；读取失败不会覆盖提交回执或自动重发写入。解析报告的 JSON 内部字段同样校验，错误结构呈现格式无效，不能导致整页崩溃。此项没有宣称所有业务写回执、版本列表或文档预览的完整契约均已覆盖。

knowledge-states-real.spec.js 在真实 localhost 桌面与手机注册隔离账号、建库、上传文本并等候真实解析；浏览器 GET 明确注入断网，成功读取和 DELETE 仍由实际服务处理。检查独立重试、真实空结果与筛选、删除提交后读取失败仍保留回执、仅一次 DELETE、SQL 文档归零和轮询自动恢复。通知 SSE 单独隔离，通知合并和迟到响应由单元测试覆盖。结束通过独立内存 Cookie 上下文调用正式账号删除并核验用户 SQL 归零；不落盘凭据或 Trace。两端安全截图只保留到视觉核对完成，随后清理。

前端部署保留原环境、标签、网络、端口和挂载，沿用唯一匹配回退组，不新增全量数据备份。仅此页面回退可切回保留的前端镜像；跨批次回退仍须遵循匹配的数据和服务协议。主项在完整矩阵通过前保持未完成。
