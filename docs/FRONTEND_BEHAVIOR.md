## 对话与阅读工作台的独立读取

对应 P3-03/P2-14 的聊天读取边界。两页共用 ChatView；会话和资料库分别通过 useIndependentRead 串行读取、取消及重试，集合字段先校验。学习记忆复用同一读取钩子，移除重复实现；知识库复用资料库集合校验。每次失效或提交回执递增代数，旧读取不能覆盖新状态；账号身份变化重新挂载整个聊天视图。

首次失败显示可重试错误，不能冒充空历史或空资料库；刷新失败保留快照并提示可能过期，禁用依赖该快照的选择、重命名、删除及检索发送。会话读取失败不阻塞当前独立回答，资料库恢复不重读会话。重试只发送对应 GET，不重发聊天或删除请求。

资料库读取失败与恢复保留输入草稿、已选范围和用户明确选择的空范围。URL 指定会话只自动选择一次；新建对话会消费待选身份，迟到历史不能抢回旧会话。已完整生成的回答不因随后刷新历史失败变为生成失败，原回答和下一轮草稿保持可读。

读取提示在现有网格中使用内容高度，正文占剩余高度，输入框保留底部空间。共享反馈允许窄容器的重试按钮换行；工具栏显式置于正文之上，资料库菜单可正常点击。手机截图先等待侧栏透明度到 1，不能使用动画中间帧验收；侧栏关闭后恢复正文交互。沿用暖白与青绿主题，修改现有样式规则，不增加覆盖样式文件。

## 学习记忆读取、保存与版本恢复

对应原审查 P3-03（记忆页面）及 P2-14（列表、候选与版本历史边界）。列表/候选读取迁入 `features/memory/useMemoryReads`，集合及渲染字段集中校验，删除页面旧组合读取；各自完成、取消、重试，重复刷新复用在途请求。本项不代表所有页面异常状态或整个渐进拆分计划完成。

### 页面行为

- 记忆列表和待确认列表分别记录首次加载、成功、失败。未取得成功结果的指标显示 `—`；只有成功返回空结果才能显示空状态。
- 部分读取失败保留另一部分成功结果。刷新失败保留已有数据和编辑草稿，并明确提示记录可能过期；用户可以独立重试。列表过期时禁止保存、状态、恢复及删除；候选过期时禁止确认/忽略。账号切换重建页面隔离旧结果。
- 保存、确认等写入回执与后续读取错误分别展示。候选确认成功先移除已消费的候选，不能因刷新失败重新显示为可确认。
- 新读取及写入会使旧列表读取失效。写入期间锁定条目选择，迟到读取不能覆盖已保存结果。
- 版本历史由 `features/memory/MemoryVersions.jsx` 独立负责读取、重试和失效保护。切换条目、卸载或版本刷新后的旧响应不能污染当前选择。
- 版本读取失败保留缓存并提示过期，禁用恢复；不显示假“零版本”或“暂无历史”。保存成功后的版本刷新失败不会改成“保存失败”。
- 恢复成功以服务端返回的记录更新正文、主题、标签和状态，再重新读取版本。
- 窄屏搜索独占一行，图标不压缩、输入不换行；真实浏览器验证移动端输入可用宽度至少 250px，并实际输入、清空搜索词。

### 实际传输故障

真实站点回归发现 Gateway 的默认 `SimpleClientHttpRequestFactory` 使用 HttpURLConnection，不能发送记忆编辑所需的 PATCH，导致实际保存返回 500。主要业务客户端改用 JDK HttpClient，明确固定 HTTP/1.1，禁止跟随重定向，连接超时 30 秒、读取超时 120 秒。原有个人模型、内部服务认证及 Trace 拦截器保留；监控和灾备的专用客户端不变。

真实 HTTP 单元回归验证 PATCH、中文正文与标签、HTTP/1.1、无 h2c Upgrade，以及内部凭据不发送给其他 origin。真实浏览器回归再通过实际 Gateway/Agent/数据库验证保存和恢复，不 mock 写入。

重复回归还发现内部服务限流 429 被通用异常处理误报为 500。Gateway 现在返回统一的 429 与受限的 `Retry-After` 秒数，不转发内部响应正文或其他头；无效重试时间回退到 1 秒。测试只对真实 429 按该时间有界重试，500 不重试，也不通过调高生产限流掩盖错误。

账号删除汇总验收进一步发现，Agent 原先按 Gateway IP 共用一个令牌桶，删除读回与状态轮询耗尽预算后，正常聊天也被拒绝。现在同一来源 IP 固定分为推理（同步聊天、流式聊天、测验）、普通交互与清理核验三类预算，各自沿用 `INTERNAL_RATE_LIMIT_BURST`（默认 60）及 `INTERNAL_RATE_LIMIT_PER_SECOND`（默认 1）；不是逐用户配额，多个 Gateway/Agent 实例也不是分布式共享预算。鉴权仍在限流之前执行，任意路径、用户头及新用户不能创建额外预算。429 的 `Retry-After` 按实际缺额与补充速率向上取整。

`answer-terminal-real.spec.js` 设置 `MNEME_RATE_LIMIT_QA=true` 后，先通过真实 Gateway 隐私读取耗尽内部服务预算，再验证聊天完成时立即断流、数据库答案与引用、重复请求及刷新。仅在隔离验收环境启用压力步骤；普通真实回归保留全部落库断言。2026-11-04 localhost 桌面、手机两项通过；中间件、鉴权及生命周期定向测试 26 项通过。

## 运维与审计独立读取状态

### 状态与权限

- 运维快照与操作审计各自串行轮询、加载、报错和重试；慢快照不会阻塞已返回的审计。初次失败不显示“暂无记录”。只有成功返回的空数组才是空记录。
- 刷新失败保留上次成功数据，并明确提示可能过期。重试审计不重发快照请求；全局刷新同时读取两者。
- 审计响应不是数组时报错。快照允许部分字段缺失，缺失表格显示不可用；任务查询状态不是 `available` 时不展示部分任务结果。监控不可用时不把告警解释为零条。

- 凭证仅在当前挂载的组件内使用。锁定卸载两个读取器，取消请求、清空缓存与凭证；旧请求即使迟到也不能污染新凭证的数据。凭证不写浏览器存储。
- 普通用户仍由真实 Gateway 拒绝；管理员还需有效的独立管理员凭证。前端的解锁按钮不是授权依据。

## 恢复演练：读取、提交与凭证隔离

## 复习卡与学习计划的独立读取

### 行为与边界

- 卡片和计划分别加载、失败、重试；尚未成功读取的指标显示 `—`。首次失败不能显示“今天的复习已就绪”“还没有计划”或空日历，只有成功空结果才能显示空状态。
- 读取失败保留缓存并提示可能过期；只重试失败部分，不重置其他数据、当前翻面或未提交计划草稿。
- `features/review/useReviewData.js` 复用共享 `useIndependentRead`，删除原重复读取实现。集合、唯一正整数 ID、文本、计数及真实日历日期/时间由 `reviewValidation.js` 校验；无效数据作为读取失败处理。新读取、卸载、账号切换或提交后的迟到响应不能覆盖当前结果。
- 创建计划仅在合法回执的标题、目标、日期与输入一致时清理草稿并显示成功；后续列表刷新失败分别提示，不改成“创建失败”或重发创建。评分回执必须归属当前卡片、次数增加且评分一致（如返回）；刷新中或读取失败时禁止基于旧卡片评分。
- 写入异常或回执损坏时保留草稿/翻面，提示“结果尚未确认”并锁定后续写入。核对按钮仅 GET；相关区域全部读取成功后，用户明确点击“已核实，继续操作”才解除锁定。核对失败不能解除，计划核对列表在手机弹窗内部可读；关闭弹窗后外层保留核对入口。核对按钮不触发表单提交。
- 保护仅限当前挂载的客户端，不是服务端持久幂等或恰好一次：刷新、离页不能撤销可能已经落库的操作，再次 POST 可能重复。页面说明该边界；不自动重放评分或计划创建。成功评分直接使用服务端到期时间和次数。
- 翻面绑定卡片 ID，切换到另一张卡不会自动暴露其答案。保留到期时钟，未来卡片到期后无需刷新即可复习。

### 部署与回退

只涉及前端和回归入口，无数据库迁移或 API 修改；沿用现有 CSS、主题和共享反馈。替换前端前核对原配置、数据挂载和现有匹配回退组，不另复制数据库；失败恢复旧镜像与配置，无需回退数据库。

## 整站恢复：读取、归档校验与接受回执

对应原审查 P3-03、P2-14，沿用 P3-02/P3-04 的共享状态、日期、大小和反馈组件。只拆整站执行器页面的数据边界；不改备份格式、执行器权限、恢复算法或既有 API，不将完整恢复演练或整份审查提前标记完成。

### 行为

首次读取、空历史与失败分开。历史串行轮询并合并手动刷新；刷新失败保留缓存，明确提示可能过期，同时暂停备份、校验和恢复。读取未成功、正在读取或有 queued/running 任务时不能提交。数组、可渲染字段和报告指标先校验，错误响应显示可重试失败，不导致渲染崩溃。后台状态与恢复阶段使用共享 formatter。

归档校验使用独立 AbortController 和最新请求身份。切换归档清除原校验，取消旧请求；即使旧请求忽略取消后迟到，也不能覆盖新选择。重新校验时先撤销原成功，失败不能保留“通过”。历史中的归档消失或大小改变同样撤销校验。恢复只提交当前选择的已验证摘要；宿主机仍在接收和执行前重新核对内容哈希，防止同名、同大小归档内容变化。

每个凭证对应独立挂载作用域。锁定或更换凭证会清空归档选择、预览、历史、对话框和回执，取消历史、校验、提交的客户端等待；迟到响应不能进入新作用域。历史 401/403 清空旧数据与校验。凭证只在内存，不进入 localStorage/sessionStorage。

提交在业务 hook 内以同步锁防重复，并在确认时重新检查历史和当前归档，已打开的危险确认框不能绕过后来发生的失败。接受响应必须是匹配当前操作的有效任务，显示“已接受”而非完成；后续刷新失败不覆盖回执。该任务出现在历史前阻止重复提交，之后仍按 queued/running 状态阻止并发任务。提交异常表示结果未确认，不自动重发；先成功刷新历史核实后才重新允许人工操作。客户端取消不能撤销已发给宿主机的任务，刷新或重新解锁后必须检查真实历史。

### 验收与边界

单元回归覆盖首次失败与重试、非法响应、串行刷新、缓存过期、归档竞态、失败撤销原成功、归档变更、已打开确认框、重复提交、接受后读取失败、未确认提交和权限撤销。全量前端测试、Lint、生产构建和原包大小门禁必须通过。

site-recovery-states-real.spec.js 在实际 localhost 桌面与手机注册隔离账号，真实验证普通用户和错误管理员凭证的 403，并检查管理员实际 GET。未配置宿主机执行器时必须显示真实 400 错误，不能伪装空历史。随后浏览器历史 GET 和只读归档校验 POST 使用明确夹具验证故障、过期、响应归属与锁定；没有调用真实归档校验或创建整站任务，不宣称已完成生产恢复演练。测试阻止所有未明确夹具化的恢复类非 GET 请求，必须计数为零。QA 账号通过正式删除接口清理，凭证和自动 Trace/录像均不落盘；仅保存明确安全的视口截图。测试加入完整栈 CI；最终本地证据和 PR 结果记入整改记录。

实际执行器 GET 依据 Gateway 当前环境分别核对：未配置 URL 或有效凭证时必须返回准确的未配置 400；已配置但执行器未启动、超时或拒绝时必须返回对应的明确错误并呈现失败状态；成功时必须返回有效历史。CI 配置了 URL/凭证但此阶段尚未启动宿主机执行器，不能将该状态误判为“未配置”。不接受其他任意 400，也不为覆盖配置分支启动真实恢复任务。

无新依赖、配置或数据库迁移。部署保留前端镜像、配置与匹配的停写快照；本地先停全部应用写入者导出 SQL，保留旧容器再切换前端。仅本项前端可切回保留镜像；跨其他批次变更回退必须按相应文档恢复匹配点，不能只恢复旧 SQL。

## 个人恢复：校验归属、未知结果与下载生命周期

对应原审查 P3-03、P2-14，并沿用 P3-02/P3-04 的共享日期、大小、反馈和状态组件。本项只拆个人恢复请求边界，不修改归档格式、服务端恢复算法或现有 API。无新增依赖、配置、CSS 或数据库迁移。

### 行为

请求迁入独立 hook，删除页面原请求实现。重新校验先撤销旧成功；失败不能保留“通过”。改变文件或范围取消旧校验，响应还必须属于当前选择和请求，即使传输忽略取消也不能覆盖新预览。校验响应检查范围、大小、摘要、兼容性、恢复模式、覆盖数量和可渲染字段，非法响应明确失败。恢复提交重新检查当前预览、步骤及确认语句，同步锁阻止重复 POST。

成功导入显示关系数据提交和文件恢复数量，索引仍需等待任务完成后验证，不冒充全部检索已就绪。提交失败或非法回执视为结果未确认，撤销旧校验并阻止当前挂载中的重复提交；用户须到资料库、会话或学习页核实后，明确点击“已核实结果，重新选择归档”。重置同时清除真实文件输入。

该限制是当前挂载中的客户端保护，不是服务端持久幂等。离页、刷新或客户端取消不能撤销服务端已接受的导入；重新进入前仍须核实真实数据，重复导入可能产生副本。后续跨请求持久去重必须独立设计，不可把本项描述为恰好一次恢复。

离页取消校验、提交和下载等待，拒绝迟到更新；下载在读取响应体后再次检查取消，即使响应体忽略取消也不能再创建下载链接。账号 ID 改变重新挂载整个恢复视图，个人预览、下载记录和管理员数据不会留给下一账号。切换页面标签仍保留当前个人向导，不把标签切换误认为服务端操作撤销。

本地提交回执使原在途 GET 失效，排队一次新读取，避免旧状态覆盖已提交状态。删除、解析显示任务已提交，最终结果仍以任务中心及后续真实列表为准；读取失败不会覆盖提交回执或自动重发写入。解析报告的 JSON 内部字段同样校验，错误结构呈现格式无效，不能导致整页崩溃。此项没有宣称所有业务写回执、版本列表或文档预览的完整契约均已覆盖。
