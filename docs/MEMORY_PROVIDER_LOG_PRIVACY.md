# 供应商错误日志的正文隔离

对应审查 P1-04 / MN-004，补查意图识别、实时反思降级及短期摘要路径。供应商异常可能包含提示词或记忆正文，不能把异常字符串或堆栈直接输出到普通服务日志。

这三条异常路径只记录异常类型、阶段、结果和哈希用户/会话身份。历史恢复、摘要开始、成功与冷却日志也不再包含原始会话编号；消息数和 token 数保留用于诊断。摘要失败仍保留原历史，不写入成功冷却时间，不改变现有降级行为。

单元测试覆盖失败和成功路径，断言日志不含正文或原始身份、保留 trace ID、无异常堆栈。实际 `memory-outbox-real.spec.js` 在隔离 QA 账号的聊天请求中只注入供应商异常，执行实际三条降级路径和 Trace 存取；摘要使用独立临时历史，不改用户实际历史。唯一私密标记不进入网页、截图或报告。测试同时捕获 Agent/Gateway 标准输出与标准错误，检查标记不存在，并扫描测试输出目录的 JSON/TXT/LOG 文件。现有回答保留、候选故障入库、重启、重试、向量确认与刷新回归继续执行；自动 Trace、录像和失败截图关闭，只生成明确的安全截图。

此项保证所覆盖生产诊断路径的正文隔离，不代表授权用户业务数据或供应商请求没有正文，也不能证明任意未来日志都已安全。新增诊断仍应默认元数据，避免异常正文与提示词进入日志；不依赖关键词脱敏识别任意自然语言。实际验收记录见 [整改记录](CODE_REVIEW_REMEDIATION_20261031.md)。

无数据库迁移、配置或依赖变更。升级保留镜像、配置及匹配数据快照；回退旧镜像会重新引入相应日志风险。敏感日志及既有备份按部署方既定保留策略管理，本项不声称已擦除历史外部日志。
