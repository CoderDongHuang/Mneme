# 邮箱验证与密码恢复

邮箱必须先证明所有权，才能用于找回密码。登录后在“个人资料”保存邮箱，点击“发送邮箱验证码”，将邮件中的完整验证码复制到同页并确认。验证成功会保存状态；修改或清空邮箱立即撤销验证，必须重新验证新邮箱。仅修改昵称或邮箱字母大小写不撤销验证。

验证码使用 32 字节安全随机数，15 分钟有效，每个用户只保留一个当前验证码；60 秒内不能重发。重发成功使旧码失效，SMTP 失败则回滚替换。数据库只保存 SHA-256 摘要，不在接口响应、日志或运维状态展示验证码。验证码绑定登录用户和已保存邮箱，只能消费一次。发送受认证、同源与接口限流保护；确认不接受未保存邮箱或其他用户的验证码。

未验证邮箱的密码恢复请求继续返回通用提示，避免暴露账号是否存在；不会创建重置码或发送重置邮件。重置确认也会再次检查邮箱已验证和账号有效，不能仅靠旧的重置码绕过。换绑邮箱与重置操作锁定同一用户行，换绑同时撤销两类验证码；头像等旧实体更新不能覆盖邮箱及验证状态。

本地自托管在 [Mailpit](http://localhost:8025) 查看邮件；生产使用独立配置的 SMTP。SMTP 接收不代表终端邮箱一定收信。未配置、认证失败或超时返回 503，验证码不会被错误标记为已发送。若丢失登录凭据且从未验证邮箱，无法使用邮件自助恢复；部署管理员应通过既有身份核实与受控账号恢复流程处理，不能批量将历史邮箱标记为已验证。

## 升级与回滚

V29 新增 `user.email_verified_at` 与有外键级联清理的 `email_verification_token`。历史邮箱没有所有权证据，升级后全部保持未验证；现有未使用重置码也会撤销。正常登录、现有密码和数据不受影响，已登录用户应主动完成验证，再退出最后一个可用会话。管理员与普通用户使用相同验证流程。

升级前停写并创建匹配的数据库和部署配置备份，保持所有网关实例版本一致。V29 后旧网关不检查验证状态，不能与新版混跑，也不能仅回滚程序而保留新数据库；需要回滚时停服并恢复匹配的完整备份和旧版镜像，随后校验登录及恢复策略。SQL 备份含验证摘要和恢复凭据元数据，应沿用既有敏感备份策略保护。

## 验证入口

- Java `EmailVerificationTest` 使用真实 MySQL、Flyway V28→V29 升级、事务和独立工作线程；覆盖未验证重置拒绝、摘要存储、过期、单次消费、冷却、SMTP 失败回滚、换绑/清空、其他租户与唯一性、并发确认及已读旧重置码的竞态。
- `EmailVerificationControllerTest` 覆盖输入校验不回显敏感值、HTTP 429/Retry-After 与验证读回；`PasswordResetDeliveryTest` 使用真实 SMTP socket 验证两类邮件主题与正文。
- 前端 `ProfilePage.test.jsx` 覆盖未保存邮箱、换绑、清空、发送失败、重复提交和确认后的敏感输入清空。
- `frontend/e2e/email-verification-real.spec.js` 在真实站点和 Mailpit 上分别运行桌面/移动链路：未验证不收重置邮件、验证后重置成功、旧密码/重放失败、换绑撤销旧重置码和重新验证。该用例关闭 Trace/视频/自动失败截图；仅显式保存没有验证码的状态截图。

```powershell
$env:MNEME_REAL_E2E='true'
$env:MNEME_E2E_BASE_URL='http://localhost:3000'
# 在 frontend 目录；Mailpit 默认 http://127.0.0.1:8025，可用 MNEME_MAILPIT_URL 覆盖
npx playwright test e2e/email-verification-real.spec.js --workers=1 --retries=0
```
