# 记忆蒸馏输入快照与候选编号

对应 2026-10-30 源码审查 P1-06 / MN-007 的重试前置条件。这一改动不等于完整后台记忆处理：当前 Python complete_conversation 仍同步运行，高置信度直接写入、摘要与反思计数尚不能整体安全重试。

## 行为

prepare_conversation 在加入本轮用户消息后、执行模型前，将消息内容、时间和本轮 request_id 复制到内存状态 memory_input。未提供请求编号的内部调用生成独立 UUID。完成时蒸馏使用该副本，不重新读取会被后续请求修改的会话缓存；空快照也不能退回实时缓存。空闲间隔以本轮开始时间计算，模型耗时不能被当作用户离开会话的时间。

待确认候选的编号由用户、会话、本轮请求和规范化候选字段共同计算，同一候选在同轮重排或重复应用时编号不变；不同用户、会话和请求互相隔离。使用 SHA-256 的前 224 位加 pending_ 前缀，总长 64，兼容既有 pending_memory.memory_id。没有快照的旧内部调用继续生成独立随机编号。

编号稳定不代表整个完成函数幂等：不能因此自动重试高置信度写入、反思计数或进度更新。快照目前只存在请求内存中；持久化后台任务及其分阶段幂等仍需独立完成。

## 验证

test_memory_input_snapshot.py 检查后续缓存变化、模型长时间延迟、空快照、消息对象复制、候选重排、租户/会话/轮次隔离及数据库编号长度。正式 Python 3.11 测试镜像运行 Ruff 与完整测试。

memory-outbox-real.spec.js 在实际项目地址运行桌面和移动端测试。夹具仅控制隔离 QA 用户/会话的回答模型和蒸馏模型输出，执行实际 complete_conversation、memory_write_node、短期缓存和反思交接。在快照后加入模拟迟到消息，检查它和当前助手回答都未进入蒸馏提示；重复执行中等置信度记忆节点，检查候选一致。后续 Gateway INSERT 故障、进程重启、任务重试、候选唯一性及真实向量确认沿用正式服务。

测试结束恢复 Agent 源文件并重启，删除触发器和 QA 用户；独立读回数据库、健康状态和夹具残留。不得把夹具控制的模型输出作为真实模型语义质量或完整后台记忆失败解耦的证据。

## 升级和回退

无新增迁移。升级前停止接收新回答，等在途请求结束，停止写入并保存匹配数据库、Agent 镜像及配置；部署 Agent 后检查健康和实际会话。前端及 Gateway 协议不变。

回退需先结束在途请求，避免同轮在新旧编号算法间切换；已经提交的候选沿用数据库中的编号。现存 memory_candidates 任务继续遵守[候选持久化任务](PENDING_MEMORY_OUTBOX.md)的升级/回退规则，不能删载荷绕过恢复。含环境变量及数据库内容的本机 artifacts 仅作私有验收证据，不能提交。
