# Mneme 项目审计与迭代路线图

> 审计日期：2026-09-16
> 审计基线：`release/v2` 及本次修复
> 项目定位：个人与小规模团队本地自托管的 Beta 学习助手

## 1. 审计结论

Mneme 已经具备可运行的核心闭环：账号认证、资料库、异步文档解析、结构化 RAG、SSE 对话、引用展示、三级记忆、学习计划、复习卡片、测验、数据导出和 Docker 自托管。React、Java、Python 三层职责总体清楚，浏览器只访问 Java，用户身份由 JWT 注入，Python 通过内部令牌隔离。

当前版本适合作为开源 Beta 和个人自托管项目，不宜描述为无需验证即可上线的完整生产级平台。近期、中期与长期路线图的仓库内功能已经实现；剩余工作属于目标领域数据评测、外部服务启用和发布环境容量/故障演练，不能由离线单机测试代替。

## 3. 功能成熟度

### 3.1 认证与用户资料：基本到位

已实现注册、登录、JWT、HttpOnly Cookie、退出、资料修改、密码修改、密码重置、头像和账号删除。Java 会从可信 JWT 中取得用户 ID，不接受前端伪造身份。密码使用 BCrypt，重置令牌只保存 SHA-256 摘要并设置 15 分钟有效期。

本轮修复了头像存储路径：Docker 环境统一写入 `/data/avatars`，由现有 `./data:/data` 挂载持久化，避免重建 Java 容器后头像消失。

本轮已补齐后台删除 Saga：接口先将账号置为 `deleting` 并写入任务，定时 worker 通过条件更新原子抢占，按知识、记忆、会话、对象/本地文件、头像和用户记录逐步清理。步骤可幂等重放，失败按指数退避重试，进程中断或锁超时后会从最后成功步骤恢复，达到上限才标记 `deletion_failed`。

### 3.2 资料库与文档解析：核心可用

支持 PDF、DOCX、PPTX、XLSX/XLSM、CSV、Markdown、TXT、HTML。PDF 包含文本块排序、重复页眉页脚过滤、表格抽取、低文本页 OCR 和可选多模态图片理解。解析失败会进入重试任务，并把错误状态返回前端。

本轮修复 Java/Python 格式契约不一致：`.markdown` 现在可以通过网关上传。

本轮已补齐单文档删除、重新解析、替换和版本恢复：版本保存 SHA-256、大小和原文件位置，恢复复用原 `document_id` 重建索引，删除会清理全部版本文件、Chroma 片段和关系记录。上传会校验扩展名、MIME、文件签名、Office ZIP 路径、危险条目、条目数量和展开总量，并提供 ClamAV INSTREAM 可选扫描、超时及 fail-open/fail-closed 策略。

- Compose 提供可选 `security` profile 运行 ClamAV；生产环境应启用扫描并使用 fail-closed，本地开发默认关闭。
- OCR 已记录页级置信度，文档预览会返回页级解析报告并醒目标记低置信度页面。
- 已加入带标注的扫描页、多栏、跨页表格、公式和电子表格图表回归夹具；目标领域模型准确率仍需由部署方持续采样评测。

### 3.3 RAG 与引用：可用但评测不足

检索结合 Dense、BM25 风格词法评分和 RRF 融合，包含确定性查询改写、重复片段过滤和上下文预算。chunk 带文档 ID、来源、页码、章节和类型，回答引用可以回到证据片段。资料不足时 Prompt 要求区分资料事实与一般知识。

本轮质量能力：

- 已增加 SQLite FTS5 持久化词法索引，文档写入、替换、删除和用户/知识库清理会同步维护；索引不可用时保留 Chroma 扫描降级。
- 已增加 DashScope 在线重排和可选本地 Cross Encoder 两种后端；默认关闭，开启后可直接使用现有 DashScope SDK，服务不可用时确定性降级到 RRF。
- 评测集已扩展到 110 条，并新增可重复生成的扫描 PDF、复杂表格、多栏、跨页、公式和图表标注夹具。
- 已增加 Recall@K、MRR、Faithfulness proxy、Citation Precision/Recall、P95 延迟和输入费用估算；`--llm-sample-size` 可显式运行真实回答/评判模型的 Faithfulness 与 Answer Relevance，并记录样本明细和费用假设。

### 3.4 Agent 与 Prompt：基础路由到位

LangGraph 已区分问答、回顾、建议和普通交流，并按意图选择知识与记忆上下文。Prompt 构建、模型调用和记忆回写已经拆分，不是单一接口内堆叠全部逻辑。

意图识别已有规则快速路径，复杂问题使用带结构化输出重试的 LLM 分类，异常时退回 general。Agent 工具通过统一注册表执行，包含输入类型校验、超时、重试、调用审计和配置化字段脱敏；知识检索节点已走该执行器。新增工具只需注册契约和处理器，无需修改执行框架。

### 3.5 三级记忆：核心机制可用

工作记忆、Redis 短期记忆和 Chroma 长期记忆已经接通。长期记忆支持偏好、薄弱点、进度、语义去重、重要度、冻结和用户确认。Redis 不可用时降级到进程内存。

本轮一致性能力：

- 长期记忆缓存以 Redis 用户修订号实现跨进程失效，Redis 不可用时使用进程内修订回退；双管理器一致性已有自动化测试。
- 账号清理已升级为带状态、重试、锁恢复和幂等步骤的后台任务。
- 记忆版本快照和恢复已接入；蒸馏记忆会保存来源会话和来源消息哈希证据链，不复制原始对话正文。
- 冻结、版本恢复、来源会话/证据哈希和跨管理器缓存失效均有自动化覆盖；发布验收仍应运行真实跨会话 E2E。

### 3.6 学习工作台：功能存在但部分为基础版

学习计划、复习卡、SM-2 风格间隔调整、知识测验、会话分支、检索调试和导出均有真实数据库实现。

需要明确边界：

- 测验支持基于证据的结构化 LLM 出题、确定性回退和关键点评分；工作区导出可批量评估结构有效性、证据/来源覆盖，并可选真实 LLM 抽检 grounding、clarity 和 answerability。
- 导出与导入支持关系数据和受限原文件归档；导入会核对 manifest、SHA-256 与归属映射，恢复原文件、文档版本并自动创建解析/索引重建任务。
- 会话分支会校验来源消息确属原会话；Testcontainers 覆盖两个并发事务创建独立分支及消息副本。
- 工作台已提供上述实时指标，并按用户保存每日快照、提供 7 至 365 天趋势 API 和 30 天测验趋势视图；数据保存在服务端，可跨设备查看。

### 3.7 可靠性与可观测性：基础到位

已有任务重试、废弃锁恢复、模型主备切换、熔断、Redis 降级、健康检查、Prometheus 指标、trace ID 和审计日志。Caddy 已将 `/api/*`、`/ws/*` 与 SPA fallback 分离。

任务领取和账号删除任务均使用数据库原子条件更新，废弃锁可恢复，关键跨存储操作写入 operation log。Agent trace 支持配置化递归脱敏并以哈希保留关联能力。Testcontainers 增加双实例竞争同一恢复任务的原子抢占测试；真实容量压测和故障注入仍属于发布环境验证项。

## 5. 下一阶段实施顺序

### P0：数据一致性与可信删除

目标：用户点击删除后，MySQL、Chroma、Redis、资料文件和头像都可验证地清理。

1. 新增 `account_deletion_task` 或通用 outbox 事件。
2. 账号先进入 `deleting` 状态并禁止新请求。
3. 分步骤删除知识集合、长期记忆、短期会话、资料文件和头像。
4. 每一步记录状态、错误和重试次数；全部完成后再删除/匿名化用户行。
5. 增加故障注入测试：Python 不可用、文件被占用、任务重复执行、服务中途重启。

### P0：单文档生命周期

增加单文档删除、重新解析、替换版本和解析报告。删除必须同时清理 Chroma 中该 `document_id` 的 chunk，重新解析需要幂等键，避免重复向量。

### P1：RAG 质量升级（已实施基础能力）

1. 建立 BM25 + Dense Hybrid Retrieval。
2. 增加查询改写和 Cross Encoder 重排。
3. 根据 token 预算动态选择片段并去除重复上下文。
4. 建立至少 100 条虚构但接近真实结构的评测集。
5. CI 跑离线召回指标，定期任务跑真实模型忠实度与费用评估。

已实现 FTS5 BM25 风格词法索引与 Dense 的 RRF 混合召回、确定性查询改写、重复片段过滤和动态上下文预算，并提供 DashScope/本地 Cross Encoder。110 条离线数据用于稳定回归，复杂版式夹具用于解析边界回归，真实 LLM 评分器用于显式抽样验收；目标领域人工样本扩充属于持续质量工程而非缺失功能。

### P1：测验与学习闭环（已实施）

让 LLM 按检索证据生成结构化题目，服务端用 JSON Schema 校验。选择题保存解析与证据；简答题采用“关键点覆盖 + 引用证据 + LLM 评分”并展示评分依据。错题自动生成复习卡并写入薄弱点候选记忆。

题目现在由 LLM 严格依据检索证据生成，并经 Pydantic/服务端双重结构校验，保存关键点、证据和来源；模型不可用或输出不合法时自动使用确定性证据题目。简答题按关键点覆盖评分，反馈显示依据；错题自动生成复习卡和待确认薄弱点记忆。

### P1：完整导入导出（已实施关系数据）

为导出定义版本化 JSON Schema，使用旧 ID 到新 ID 的映射恢复会话、消息、计划、复习卡、测验和分支。资料原文件和向量应通过独立压缩包导入，并限制压缩炸弹与路径穿越。

当前 schema `mneme.workspace` v2 已完整恢复关系型学习数据及测验作答记录，并设置单类数据 10000 条、文本长度和 JSON 合法性限制。归档包携带受限原始文件副本和文档清单；导入会先验证条目归属和 SHA-256，再写入租户存储、建立文档初始版本并创建解析任务自动重建 Chroma 索引。manifest 不包含服务器内部 `file_path`，并拒绝非法 ZIP、路径穿越、未知/重复条目、文件数量超限和解压大小超限。

### P2：体验与运维（基础项已实施）

- 前端已增加逐文件上传队列、成功/失败状态和错误详情；文档级重试与任务中心已存在。
- 引用原文高亮、页码定位、失败任务重试、任务通知和页级解析报告已具备基础实现。
- 模型、Embedding 与多模态配置检查页已提供脱敏状态，不在浏览器保存密钥。
- 增加 OpenTelemetry、结构化性能指标和慢检索追踪。
- 提供数据迁移命令、备份校验和恢复演练脚本。

Python `/health/config` 已提供不含密钥值的配置状态，Java 已代理该接口，前端“服务配置”页可查看就绪状态；密钥本身不会进入浏览器。

## 8. 当前推荐版本定位

推荐 GitHub 简介继续使用：

> Mneme 是一个支持结构化 RAG、三级记忆和可追溯引用的开源个人学习助手，采用 React、Spring Boot、FastAPI、LangGraph、Chroma、MySQL 与 Redis，面向本地自托管。

发布标签应使用 `Beta`，不要使用“生产级”“支持任意复杂文档”或“完全准确”等无法由当前测试证明的表述。
