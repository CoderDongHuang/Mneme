# Mneme 项目审计与迭代路线图

> 审计日期：2026-09-12
> 审计基线：`release/v2` 及本次修复
> 项目定位：个人与小规模团队本地自托管的 Beta 学习助手

## 1. 审计结论

Mneme 已经具备可运行的核心闭环：账号认证、资料库、异步文档解析、结构化 RAG、SSE 对话、引用展示、三级记忆、学习计划、复习卡片、测验、数据导出和 Docker 自托管。React、Java、Python 三层职责总体清楚，浏览器只访问 Java，用户身份由 JWT 注入，Python 通过内部令牌隔离。

当前版本适合作为开源 Beta 和个人自托管项目，不宜描述为完整生产级平台。主要原因不是“无法运行”，而是部分高级功能只有基础实现，真实 RAG 评测数据规模也不足。账号删除和单文档生命周期的 P0 实现已完成，但仍建议通过故障注入和多实例场景继续强化补偿机制。

## 3. 功能成熟度

### 3.1 认证与用户资料：基本到位

已实现注册、登录、JWT、HttpOnly Cookie、退出、资料修改、密码修改、密码重置、头像和账号删除。Java 会从可信 JWT 中取得用户 ID，不接受前端伪造身份。密码使用 BCrypt，重置令牌只保存 SHA-256 摘要并设置 15 分钟有效期。

本轮修复了头像存储路径：Docker 环境统一写入 `/data/avatars`，由现有 `./data:/data` 挂载持久化，避免重建 Java 容器后头像消失。

本轮已补齐：删除账号会先调用 Python 清理 Chroma 集合、长期记忆、Redis 短期会话和会话元数据，再清理本地资料与头像，最后让 MySQL 外键级联删除业务数据；任何外部清理失败都会阻止用户行删除。后续仍应将该同步流程升级为带状态和重试的账号删除任务，覆盖进程中断和多实例场景。

### 3.2 资料库与文档解析：核心可用

支持 PDF、DOCX、PPTX、XLSX/XLSM、CSV、Markdown、TXT、HTML。PDF 包含文本块排序、重复页眉页脚过滤、表格抽取、低文本页 OCR 和可选多模态图片理解。解析失败会进入重试任务，并把错误状态返回前端。

本轮修复 Java/Python 格式契约不一致：`.markdown` 现在可以通过网关上传。

本轮已补齐单文档删除和重新解析：两者都通过 Java 任务队列执行，删除会清理 Chroma 片段、原文件和 MySQL 元数据；重新解析复用原 `document_id`，先删除旧片段再写入新片段，避免重复召回。仍需改进：

- 增加单文档删除与重新解析接口，而不是只能删除整个资料库。
- 上传校验应继续加入 MIME/魔数映射、压缩包解压大小限制和恶意文档扫描。
- OCR 应记录页级置信度；低置信度页面需要在前端提示用户核验。
- 表格、公式、多栏和流程图需要建立专项测试集，不能只验证“能抽出文本”。

### 3.3 RAG 与引用：可用但评测不足

检索结合向量相似度和轻量词法匹配，能改善编号、姓名、术语等精确 token 的召回。chunk 带文档 ID、来源、页码、章节和类型，回答引用可以回到证据片段。资料不足时 Prompt 要求区分资料事实与一般知识。

仍需改进：

- 当前词法召回不是正式 BM25 索引，文档增多后性能和排序质量会下降。
- 增加 Query Rewrite、Metadata Filter、Cross Encoder 重排和上下文压缩。
- 评测集需覆盖 PDF 表格、扫描件、跨页问题、否定问题、无答案拒答和多文档冲突。
- 指标除 Hit@K、MRR 外，还应加入 Faithfulness、Answer Relevance、Citation Precision/Recall 和延迟/费用。

### 3.4 Agent 与 Prompt：基础路由到位

LangGraph 已区分问答、回顾、建议和普通交流，并按意图选择知识与记忆上下文。Prompt 构建、模型调用和记忆回写已经拆分，不是单一接口内堆叠全部逻辑。

仍需改进：意图识别目前依赖一次 LLM 分类，异常时退回 general。建议增加规则快速路径、结构化输出重试、节点级超时和执行轨迹持久化。复杂任务应引入显式工具调用，而不是仅靠 Prompt 描述行为。

### 3.5 三级记忆：核心机制可用

工作记忆、Redis 短期记忆和 Chroma 长期记忆已经接通。长期记忆支持偏好、薄弱点、进度、语义去重、重要度、冻结和用户确认。Redis 不可用时降级到进程内存。

仍需改进：

- 记忆确认在 Java 与 Python 间有两套状态，需要增加最终一致性和幂等测试。
- 账号删除必须清理 Chroma 长期记忆。
- 增加记忆来源、证据消息、版本和撤销历史，使画像变化可解释。
- 冻结、过期和反思策略需要更多跨会话 E2E，而不只是单元测试。

### 3.6 学习工作台：功能存在但部分为基础版

学习计划、复习卡、SM-2 风格间隔调整、知识测验、会话分支、检索调试和导出均有真实数据库实现。

需要明确边界：

- 测验题由检索片段模板生成，不是高质量的 LLM 出题与判分；简答题当前主要按长度判断，不能代表语义正确。
- 导出包含资料库、会话、消息、计划、复习、测验和分支，但导入当前只追加学习计划。前端已经写明“导入学习计划”，仍应给导出文件增加 schema 并实现完整恢复或改名为“导入计划”。
- 会话分支复制消息，但需要补充来源消息归属校验和并发分支测试。

### 3.7 可靠性与可观测性：基础到位

已有任务重试、废弃锁恢复、模型主备切换、熔断、Redis 降级、健康检查、Prometheus 指标、trace ID 和审计日志。Caddy 已将 `/api/*`、`/ws/*` 与 SPA fallback 分离。

仍需改进：任务领取在单机 MySQL 下可用，多实例部署时应使用数据库原子条件更新并增加并发测试；关键跨存储操作需要 outbox/saga；日志应避免记录资料正文和个人敏感信息。

## 4. 本轮修复清单

1. 将间接依赖 `nanoid` 固定到无当前高危公告的版本，恢复 `npm run audit` 与 CI。
2. Java 上传白名单增加 `.markdown`，与 Python 解析器和 README 保持一致。
3. 头像路径改为配置项 `AVATAR_STORAGE_PATH`；Docker 默认 `/data/avatars`，本地默认 `../data/avatars`。
4. README 修正真实 E2E 描述，并加入本审计文档入口。
5. 移除已经失效的 React Router 安全 allowlist，当前没有 high/critical 审计例外。

## 5. 下一阶段实施顺序

### P0：数据一致性与可信删除

目标：用户点击删除后，MySQL、Chroma、Redis、资料文件和头像都可验证地清理。

1. 新增 `account_deletion_task` 或通用 outbox 事件。
2. 账号先进入 `deleting` 状态并禁止新请求。
3. 分步骤删除知识集合、长期记忆、短期会话、资料文件和头像。
4. 每一步记录状态、错误和重试次数；全部完成后再删除/匿名化用户行。
5. 增加故障注入测试：Python 不可用、文件被占用、任务重复执行、服务中途重启。

### P0：单文档生命周期

增加单文档删除、重新解析、替换版本和解析报告。删除必须同时清理 Chroma 中该 `document_id` 的 chunk，重新解析需要幂等键，避免重复向量。

### P1：RAG 质量升级

1. 建立 BM25 + Dense Hybrid Retrieval。
2. 增加查询改写和 Cross Encoder 重排。
3. 根据 token 预算动态选择片段并去除重复上下文。
4. 建立至少 100 条虚构但接近真实结构的评测集。
5. CI 跑离线召回指标，定期任务跑真实模型忠实度与费用评估。

### P1：测验与学习闭环

让 LLM 按检索证据生成结构化题目，服务端用 JSON Schema 校验。选择题保存解析与证据；简答题采用“关键点覆盖 + 引用证据 + LLM 评分”并展示评分依据。错题自动生成复习卡并写入薄弱点候选记忆。

### P1：完整导入导出

为导出定义版本化 JSON Schema，使用旧 ID 到新 ID 的映射恢复会话、消息、计划、复习卡、测验和分支。资料原文件和向量应通过独立压缩包导入，并限制压缩炸弹与路径穿越。

### P2：体验与运维

- 前端增加上传队列、页级解析报告、引用原文高亮和失败重试详情。
- 增加模型/Embedding/多模态配置检查页，但不在浏览器保存密钥。
- 增加 OpenTelemetry、结构化性能指标和慢检索追踪。
- 提供数据迁移命令、备份校验和恢复演练脚本。

## 6. 发布标准

下一次版本发布至少满足：

- 所有 CI 作业通过，安全审计无未解释的 high/critical。
- Docker 从空数据目录启动后可完成真实注册、上传、解析、RAG 与引用。
- 账号和资料删除通过跨存储一致性 E2E。
- RAG 基线有明确数据规模、阈值和失败样例，不用单个 1.0 指标宣传整体质量。
- README、接口文档、配置模板和实际端点保持同步。
- 变更日志明确兼容性、迁移步骤和已知限制。

## 7. 当前推荐版本定位

推荐 GitHub 简介继续使用：

> Mneme 是一个支持结构化 RAG、三级记忆和可追溯引用的开源个人学习助手，采用 React、Spring Boot、FastAPI、LangGraph、Chroma、MySQL 与 Redis，面向本地自托管。

发布标签应使用 `Beta`，不要使用“生产级”“支持任意复杂文档”或“完全准确”等无法由当前测试证明的表述。
