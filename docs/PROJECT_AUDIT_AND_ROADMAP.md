# Mneme 当前项目审计与路线图

> 审计日期：2026-09-19
> 审计范围：`main` 分支、P2 工程优化、自动化测试、Compose 配置、运维脚本与文档
> 项目定位：个人与小规模团队本地自托管的 Beta 学习助手

## 1. 当前结论

Mneme 的核心产品闭环已经存在：认证、资料库、异步解析、结构化 RAG、流式对话、引用、三级记忆、学习计划、复习、测验、导入导出和自托管配置均有真实实现，不是仅有页面或占位接口。

旧版文档中的历史修复记录已经删除；P0、P1、P2 和中期工作使用明确的完成标识，未完成工作继续按长期列出。

当前仍不能把项目描述为“全部功能均经过生产验证”。常规 CI 已执行真实基础设施上的全链路、跨存储删除故障注入、备份恢复、双节点扩展和供应链检查，并使用真实 Tesseract 与 Qwen-VL 做独立质量验收；常规业务流中的模型生成与 Embedding 仍使用可重复的确定性 CI 替身，真实模型样本和并发规模也有限。当前版本继续定位为 Beta。

本次复审除账号删除残留风险外，还发现并修复了 Chroma 冷启动依赖竞态、向量数据未真实持久化、非 root 日志权限、MinIO `.object-cache` 删除残留和并发创建会话分支死锁。对应用户隔离、失败传播、跨存储残留、恢复后 RAG 和 MySQL 并发测试均已加入自动化验收。

## 3. 已确认的实现范围

- Java 从 JWT 注入用户身份，Python 业务接口受内部服务令牌保护；密码、重置令牌、管理员接口和上传边界有安全测试。
- 文档支持 PDF、DOCX、PPTX、XLSX/XLSM、CSV、Markdown、TXT 和 HTML；具备版本替换、恢复、删除、解析报告、受限归档导入和索引重建。
- 检索包含 Dense、SQLite FTS5、RRF、查询改写、去重、上下文预算和可选重排器；引用保存文档、页码、区域及 OCR 元数据。
- 工作记忆、Redis 短期记忆和 Chroma 长期记忆已接通；长期记忆支持确认、冻结、来源证据、版本和回滚。
- 学习计划、复习卡、测验、错题转卡、薄弱点、会话分支、每日指标快照和趋势 API 使用真实数据库。
- 通知历史、Redis Pub/Sub、数据库轮询补偿、任务重试、废弃锁恢复、操作日志、Prometheus 指标和健康检查已实现。
- 本地/S3-MinIO 存储驱动、租户路径和配额、稳定向量分片路由已实现；共享基础设施与双 Java/Python/Chroma 实例已进入自动化验收。

## 5. 后续实施顺序

### 中期：已实现（2026-09-20）

- ✅ 已完成：**目标领域评测集版本化。** 新增学习助手领域的脱敏基准 manifest，覆盖 RAG、测验、OCR、多模态和 Embedding；数据分类、来源、版本与最小样本数由脚本强制校验。RAG/测验/文档 AI 报告统一保留失败样例，RAG 可与提交基线执行指标回归比较。当前仓库种子集来自项目领域资料，不包含或冒充真实用户记录；后续真实用户样本只能在取得合法授权并脱敏后按同一 manifest 协议加入。
- ✅ 已完成：**长时容量与多故障组合测试可执行。** 独立工作流启动 2 Java、2 Python、2 Chroma、Redis 和 Jaeger，向小/中/大三档知识库写入 61 份文档，对真实检索按配置时长执行 600 请求、24 并发，并进行 3 轮 Chroma 与 Redis 联合故障、readiness 恢复和逐库检索复查；参数可由手动调度扩大。
- ✅ 已完成：**真实模型抽检形成统一门禁。** 每周和手动工作流扩大到 8 个 RAG、6 个测验、3 个文档 AI 和 4 个 Embedding 样本；真实 LLM、Embedding、OCR 与多模态均有阈值、预算上限、脱敏前置检查、失败样例和 30 天 artifact。真实 Embedding 启用严格模式，供应商失败时禁止静默降级为本地向量；所有子门禁先上传证据再统一阻断。

中期实现的本地验收包括目标领域数据集校验、离线 RAG 门禁、版本对比和新增单元测试。真实模型与长时 Docker 结果由对应的定时或手动 GitHub Actions 生成，不把尚未执行的新周期任务误记为已获得外部运行结果。

### 长期：已实现（2026-09-21）

- ✅ 已完成：**SLO、告警与灾备演练形成闭环。** 版本化 SLO 明确 30 天可用性 99.5%、HTTP P95 2 秒、RPO 24 小时和 RTO 60 分钟；Prometheus 记录规则、错误率/可用性/延迟告警和 Alertmanager 配置可直接部署。月度及手动工作流在隔离栈执行备份、删除、恢复、恢复后 RAG 和 RPO/RTO 检查，并保留 90 天证据；容量模型继续由中期工作流按请求量、并发和三档数据规模生成。
- ✅ 已完成：**版本与轨迹辅助状态支持共享存储。** Python Agent 新增 MySQL 辅助状态后端，生产和双节点配置默认将记忆版本、脱敏 Agent 轨迹写入共享 MySQL，版本写入使用数据库命名锁避免多实例竞争；SQLite 仅作为显式的本地开发兼容后端。词法索引属于可重建派生数据，不再承担不可替代状态。
- ✅ 已完成：**工具治理实施权限、配额、隔离与审批。** 每个工具必须声明 owner、审计状态、scope、配额单位和隔离级别；执行前强制检查调用者 scope 和跨实例共享的用户日配额。高风险工具可要求管理员令牌签发的短期审批令牌；进程隔离适配器使用临时工作目录、最小环境、JSON 输入输出、超时和输出上限，未配置适配器的隔离工具会拒绝运行。参数校验、重试、脱敏轨迹和账号删除清理继续保留。
- ✅ 已完成：**学习效果采用真实观测校准。** 测验得分和复习评分写入按用户、主题隔离的效果事件；同主题数据达到样本下限后，历史保留率实际调整复习间隔，后续复习表现校准测验分，薄弱点置信度按历史掌握程度调整。接口同时返回原始测验分、观测数量、早期/近期分数、变化量和保留率；数据不足时明确标记并使用保守默认值，不用完成率 proxy 冒充用户成效。

长期实现已通过专项单元测试、Python 全量回归、Java 编译和 Compose 配置校验。月度灾备运行属于新增定时任务，首次外部演练结果应由 GitHub Actions 生成，不在实现提交前伪报为已运行。
