# 会话清单的原子写入与账号删除围栏

对应原审查 P1-05 / MN-006 的失败传播、清理清单与删除后不可复活。本项只关闭 JSON 会话元数据边界；不代表 Redis、短期/工作记忆、长期记忆及版本的全部迟到写入已经隔离。

所有修改和 TTL 裁剪从读取到发布完整持有既有用户 generation 数据库锁。两个 Store 实例的并发注册、计数不再相互覆盖；删除先持久 tombstone，等待已有写入结束，后续注册、标题、计数、删除单会话及兼容保存均拒绝。读取已删除账号返回空且不创建文件，清理接口仍可严格枚举旧清单并执行幂等删除。

仅文件不存在视为空。损坏 JSON、错误结构和 I/O 故障向上传播，不能把清理范围当空或覆盖。写入使用同目录临时文件、flush/fsync 和原子 replace；序列化、fsync 或 replace 失败保留旧字节并清临时文件，失败可重试。删除后独立检查路径不存在。原有文件名、JSON 格式和 TTL 不变。

真实八线程测试还发现 MySQL `INSERT IGNORE` 先取得重复键共享锁，再 `SELECT FOR UPDATE` 升级会发生死锁。初始化改为不覆盖任何状态的 no-op upsert，直接取得排他行锁；保留 tombstone，禁止通过重放业务体来掩盖冲突。没有新依赖、配置或数据库迁移。

## 验证

Python 3.11 Ruff、完整 877 项通过；故障及并发测试覆盖两个实例、多线程计数、发布中删除、TTL 裁剪、损坏清单、失败保留与重试、新实例迟到拒绝。实际部署脚本分别在 SQLite 和共享 MySQL 执行八线程 32 次注册与 32 次计数、在途发布和删除竞争、五种迟到修改及另一用户隔离，全部通过。脚本只延迟自己的存储调用，保留前缀合成身份和文件最终清零，不移除正式账号 tombstone。

实际 localhost 桌面/手机六项通过，无整项重试：原会话删除增加后台 completed 后的新进程迟到写检查，Trace/隐私与原隐私页面同步回归。十二张安全截图复核；独立读回 279 个删除任务全部 completed，230 个持久已删除账号的会话文件零残留，合成 SQLite/MySQL manifest、合成文件和临时文件均零，三个部署源码哈希一致，Gateway/Agent 均 200。首次 MySQL 死锁日志保留，修正后完整重跑，不将首次失败算通过。双存储脚本与真实页面均纳入整栈 CI。

## 升级与边界

文件仍是单主机缓存；多实例须同时共享会话目录与 MySQL 围栏，数据库锁不能复制本地文件。本项保证正常运行中的原子发布，不承诺目录 fsync 或断电持久性；进程被杀遗留的临时文件及物理留存仍属 P2-12。账号 tombstone 不因删文件而移除。普通删会话不等于删除账号，后续正常会话仍可创建。

实际部署先停 frontend、Gateway、Agent 全部应用写入者，保留匹配 SQL、Agent `/app/data` 目录、配置及旧容器，再切镜像。依赖锁未改，本地基于锁一致的已验收镜像复制源码，正式 CI 使用标准全量构建。回退须停全部新工作器并恢复匹配镜像和数据点；旧代码不理解围栏，不支持混跑。证据见整改记录。
