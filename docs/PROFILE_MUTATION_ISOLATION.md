# 个人资料写入与账号删除的并发约束

头像上传、修改密码、邮箱修改、密码重置及账号删除在提交用户状态时使用同一个 MySQL 用户行锁。锁内读取当前行，不能把请求开始时的整个 User 快照重新写回数据库。各操作只更新自己负责的字段。

## 头像

文件复制期间不持有用户行锁。复制完成后锁定并确认用户仍为 active，再更新 avatar_path；如果账号删除先获得锁，上传回滚，不得把 deleting 或 deletion_failed 恢复为 active。

输入流通过 try-with-resources 关闭。事务回滚（包括复制失败、数据库拒绝更新和删除竞争）清理新文件，事务提交后才清理旧文件。两个并发上传按用户行锁顺序提交，后提交者保留自己的文件并清理前一个已提交的头像。文件清理范围限制在配置的头像根目录内。

## 密码与删除

修改密码在锁内验证最新密码 hash，只更新 password_hash；全部登录会话撤销与密码修改在同一事务中。撤销失败时密码也回滚；同一旧密码的并发修改只有一个可以成功。已进入删除流程的用户不能继续读取资料、上传头像或修改密码。

删除入队只更新 status；后台失败回写也只更新删除状态，且仅接受已有 deleting/deletion_failed 的行。不会覆盖其他字段或复活账号。

## 保证范围

MySQL 事务与本地文件系统不构成原子事务。此处保证正常异常/事务回滚的清理，以及提交后旧头像清理。进程强制退出、磁盘不可写或 afterCommit 文件删除失败仍可能留下孤儿文件；清理失败仅记录异常类型，不打印用户路径。孤儿文件和备份保留属于审查 P2-12，不能据此宣称物理不可恢复删除。
