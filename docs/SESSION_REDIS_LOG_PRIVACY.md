# Redis 会话诊断隐私

对应审查 P1-04 / MN-004 的元数据日志和异常泄漏验收。本项只覆盖 `session_persistence.py` 的连接、保存、恢复、删除和残留读回；不关闭短期/工作记忆的并发和迟到写入边界。

连接成功不打印服务地址；异常只记录固定操作、结果、异常类型和已有 trace_id。保存、恢复和删除按现有 `memory_log_fields` 记录会话 SHA256 截断摘要，不输出原会话标识、消息正文、Redis 返回值或异常文本。残留计数只记录批次大小。删除和读回仍抛固定 RuntimeError，抑制原始异常链，避免上层 `logger.exception` 或标准 traceback 再次输出 Redis/Pydantic 可能携带的正文。

连接、保存和恢复维持原有降级行为，失败标记 Redis 不可用，保存仅保留内存历史、恢复返回 None；不将降级冒充可靠持久化。删除和读回保持严格失败，原删除任务可以在服务恢复后重试，不能误报删除成功。

## 验收

单元测试分别注入连接、保存、恢复、Pydantic 畸形字段、删除和读回异常，用唯一标记检查 JSON 日志、直接格式化 traceback 和上层异常 logger；确认 trace_id 和会话哈希仍能关联，且清理失败后的显式重试可完成。保留原删除残留/静默失败测试。

真实 localhost `memory-outbox-real.spec.js` 在隔离账号的正式请求中运行实际六类错误处理，只替换独立临时持久化对象的 Redis 客户端，不中断共享 Redis、不向 Redis 存放标记。临时对象作用域、供应商输出和候选写故障夹具均按测试清理恢复。实际 Gateway 重启、回答保留、候选重试、确认向量与刷新继续回归；读取两服务 stdout/stderr、实际 Trace 和文本测试产物确认动态唯一标记没有泄漏。自动录像和 Trace 关闭，只保存安全视口截图。该故障夹具不代表对生产 Redis 进行了真实网络中断。

## 升级和回退

没有依赖、配置、迁移或存储协议变化。升级仍停止全部应用写入者，保留匹配 SQL/Agent 数据、旧镜像和容器配置，再替换镜像；回退使用匹配数据和镜像。回退旧代码会重新暴露异常文本，不能据此宣称旧版本也具备本项保护。

本项不修改通用 JsonFormatter 的任意第三方日志策略，不保证异常对象在进程内物理擦除，不取消已发请求，也不宣称全部日志与整份审查完成。最终结果见整改记录。
