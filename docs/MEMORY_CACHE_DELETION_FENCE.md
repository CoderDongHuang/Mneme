# 记忆缓存删除围栏与共享失效

对应源码审查 P1-05 的跨存储清理、失败传播和独立读回，及 MN-006 的迟到写入防复活。本项覆盖长期记忆进程缓存及旧 Redis 版本键，不关闭短期/工作记忆、会话消息、P2-12 留存策略或整份审查。

## 协议与边界

共享缓存版本复用现有 generation 用户持久状态的 `memory_cache_revision`，不新增数据库表或依赖。读失败或非法版本必须报错，不降级到进程内版本。每次缓存命中也取得用户锁，检查账号 tombstone 和共享版本；读取供应商/向量库在锁外，发布时重新检查版本，版本改变则重新查询，最多三次，持续变更明确提示重试。缓存存入和返回均深拷贝，调用方修改返回值不会污染其他请求。

账号 tombstone 后，缓存读取和发布均拒绝并清除该实例本地缓存。清理不再创建 Redis 版本键；只删除旧 `mneme:memory-revision:{user}` 并独立 EXISTS 确认，静默删除残留、Redis 不可用及读错必须失败，让原删除任务重试。共享失效失败也在 finally 清理当前本地缓存。另一账号的缓存和旧键保持隔离。

无法远程立即擦除其他进程堆内存；其他实例下次访问时检查持久 tombstone 并拒绝返回旧数据。本项保证已完成失效后的旧查询不能标记为新版本，不把向量写入与随后失效宣称为跨库 ACID。存储写成功而共享失效失败时，调用方收到失败，需按真实存储核实；不自动重放非幂等写入。

## 验收

单元测试覆盖热缓存拒读、实际查询暂停期间删除、跨实例共享版本、并发更新重查、持续变更上限、深拷贝、损坏状态及历史键清理失败后重试。`python scripts/check_memory_cache_fence.py selftest` 在实际部署中分别以 SQLite/MySQL 执行，用实际 Qdrant 和当前 Embedding 配置；暂停独立脚本进程的真实存储读取结果，不替换服务进程，不修改现有向量 profile。finally 清理合成账号数据。

`memory-cache-fence-real.spec.js` 在实际 localhost 桌面和手机注册隔离账号，运行竞态，核对另一账号更新后的实际正文、页面及详情；最后通过正式 DELETE 删除账号，等待持久 tombstone、向量零残留及历史 Redis 键归零，再用新进程拒绝迟到发布。自动 Trace 和录像关闭，仅保存安全视口截图；既有记忆编辑、历史恢复及会话清理同时回归。双后端脚本及真实页面回归加入完整栈 CI。最终结果见整改记录。

## 部署与回退

升级后运行 `python scripts/cleanup_deleted_memory_revisions.py` 清理旧版本在账号删除后遗留的 Redis 版本键；使用与服务一致的 `AUXILIARY_STORE_BACKEND`。历史上若曾使用两种持久后端，分别核验并运行。扫描只处理存在持久 tombstone 的准确用户键，活账号和其他键保持不变，状态读取失败立即停止，删除后独立读回，再扫描确认；安全幂等重跑。仅 Redis 返回可信完整扫描时才能据此确认扫描范围，不宣称防御失真的后端协议。

没有新配置、迁移或依赖。SQLite 用于单主机共享文件，多副本必须一致使用共享 MySQL。升级先停止全部应用写入者，保存匹配的 SQL、Agent 数据和旧镜像/容器配置，再切换；旧版本工作器必须停止，否则仍可绕过围栏。回退也先停全部写入者，跨批次恢复须使用匹配数据和镜像，保留 tombstone，不让旧消费者处理已删除账号。逻辑清理不等于 SQLite WAL、磁盘空闲页或历史备份的物理不可恢复擦除。
