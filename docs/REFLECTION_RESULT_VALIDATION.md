# 反思结果校验与可恢复失败

对应审查 P1-06 / MN-007 和 P2-01。此前 `run_reflection` 对非法 JSON 返回空对象，队列因未抛错而确认任务并扣减计数。现在区分“没有记忆可分析”和“供应商返回无效结果”：前者仍正常跳过，后者抛出固定消息的 `ReflectionResultError`，不携带供应商原文或原 JSON 解析异常上下文。

结果必须是包含三个准确字段的 JSON 对象：`implicit_preferences` 和 `priority_weak_points` 为字符串数组，`next_step_suggestion` 为字符串。非字符串响应、非法 JSON、额外或缺失字段、错误字段类型一律失败；不会把 Markdown 包裹或错误输出当作有效反思。

后台消费者沿用所有权协议：失败保留 Stream pending、任务预约和计数，执行租约过期后由新 owner 接管；合法结果才能原子确认并扣减。即时学习建议仍沿用安全降级，不因反思无效覆盖回答。本项没有引入无限的立即网络重试；现有反思队列按租约周期重试，仍需后续统一后台任务状态与长期故障处置，不代表完整记忆流水线已异步化。

单元测试覆盖格式/字段错误、成功、无数据跳过，以及失败保持计数和恢复后的唯一完成。`scripts/check_reflection_lease.py` 在独立 QA Stream 使用真实 Redis、Lua、pending、过期接管：注入无效模型输出后确认 pending 和计数保留，改为合法输出后新 owner 完成且重放不再次调用模型。此段只替换模型、测试记忆输入及授权检查，不宣称已验证外部供应商或隐私授权；相关授权仍由既有测试覆盖。脚本同时保留心跳、崩溃接管、旧 owner 拒绝和旧协议迁移验收，并由整栈 CI 运行。

实际聊天回归在隔离 QA 请求中运行实际反思解析器和即时建议降级，继续验证回答保留、候选故障、重启、重试、向量确认及刷新，并检查日志与 Trace 不含私密标记。真实页面、完整测试及独立读回结果见 [整改记录](CODE_REVIEW_REMEDIATION_20261031.md)。

无新增依赖、配置或迁移；升级保留匹配镜像、Redis、数据库和配置快照，停止旧工作器后切换。不能混跑仍把无效结果当作成功的旧消费者；回退旧版会重新引入错误确认风险。
