# 反思会话计数的原子投递去重

对应 P1-06 / MN-007 的安全重试前置条件。本项补齐反思计数，完整记忆提取、蒸馏、持久化交接和账号删除防复活仍分别验收。

## 身份与保留

`prepare_conversation` 在模型调用前固定 `delivery_id`。完成阶段按用户、会话及该 ID 记录一次反思计数，不依赖回答正文、时间或工作器身份。Gateway 请求已有稳定 request_id；没有 request_id 的直接调用，在 prepare 或旧调用的 state 中生成并保留随机 ID。同一个没有请求 ID 的新 HTTP 请求无法识别为旧请求，不能承诺跨请求去重。

Redis Lua 在一次操作内检查投递标记、递增计数、修复没有过期时间的旧计数，并写入标记。会话及请求身份用规范 JSON 的 SHA-256 组合，避免分隔符歧义，键不含正文或原始会话/请求 ID。用户仍沿用现有反思键的用户命名空间。计数和标记默认最多保留七天；已有计数 TTL 和重复投递标记 TTL 不因重试延长。

去重承诺限于标记保留期。已消费计数删除后，保留的投递标记仍阻止旧回答重新增量；七天后再重放不能依靠该标记去重。未来持久后台任务的重试上限及最终检查点必须与此窗口协调，不能将它当成永久完成账本。没有两种身份的旧 `record_session` 调用仍把每次调用计为不同事件；只传一半身份会在访问 Redis 前拒绝。Redis 不可用不回退本地，不报告成功。

## 验证

- 单元测试检查跨实例重投递、消费后重放、租户/会话/回答隔离、身份编码歧义、提交后响应丢失重试以及真实 complete 调用使用固定身份。
- `python scripts/check_reflection_delivery.py` 使用真实 Redis 和唯一 QA 用户，八线程跨两实例并发投递 32 次，实际验证唯一计数、消费后新实例重放、旧无 TTL 计数修复及保留时间不被延长，最后按准确键清理。
- `python scripts/verify_redis_durability.py` 在有/无密码的隔离 Redis 里，等待 AOF fsync 后 SIGKILL、重启并完成 pending 任务，再重投同一身份，确认不会重新创建计数；同时运行上述真实并发检查及原租约回归。
- 实际聊天桌面/手机回归在正式 complete 后读取对应 Redis 标记和有效期，模型输出仍只由隔离 QA 夹具控制，其余 Gateway/Agent、队列和存储按真实路径执行。
