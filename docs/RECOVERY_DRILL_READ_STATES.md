# 恢复演练：读取、提交与凭证隔离

对应审查 P3-03、P2-14，并沿用 P3-02/P3-04 的共享格式与反馈组件。本项只处理管理员 GitHub 隔离演练，不将整站执行器与个人恢复向导的所有状态提前关闭。

历史、报告、提交状态迁入 features/recovery/useRecoveryDrillData。历史首次加载与真正空列表分开；串行轮询与手动刷新合并，失败可独立重试，已加载历史在刷新失败时明确标记可能过期，不能把失败显示为无数据。历史与报告的可渲染字段校验失败会显示错误，不因畸形数组或对象导致页面崩溃。任务状态和附件大小使用共享 formatter，排队不显示为已完成。

锁定会卸载整个凭证作用域，包括整站子组件、历史、报告、确认语句与提交回执，取消读取和客户端提交等待。报告切换取消前一读取并校验最新请求身份；即使传输忽略取消，旧结果也不能覆盖新报告或新凭证作用域。凭证只存在内存，不保存到浏览器存储。历史读取出现 401/403 时不继续展示旧历史或报告。

提交使用同步锁，禁用确认输入以阻止重复提交，只在后端明确返回 accepted 后显示已提交；后续刷新失败不覆盖该回执。提交遇到网络错误表示结果未确认，提示先刷新核实，不自动重新 POST。客户端取消并不保证已经发出的 GitHub 调度被撤回；重新解锁后需读取历史确认，不能据锁定认定演练取消。完整演练的最终状态由 GitHub 历史、报告与附件决定。

## 验收范围

单元回归覆盖首次加载/失败/重试、畸形响应、串行刷新合并、报告切换与迟到结果、锁定时在途历史/报告/POST、新凭证隔离、重复提交、accepted 后刷新失败、提交结果未确认及权限撤销。完整前端、Lint、生产构建和包大小检查必须通过。

recovery-drill-states-real.spec.js 在实际 localhost 桌面与手机注册隔离账号，真实验证普通用户与错误管理员凭证返回 403、管理员读取的实际结果。当前本地/CI 未配置 GitHub 工作流凭证，真实请求应返回“恢复工作流未配置”，不能伪装成功历史。随后仅在浏览器层以明确的 GET 夹具覆盖历史/报告，验证 503、恢复、缓存过期、排队状态及锁定后的迟到响应。这部分不代表外部 GitHub 工作流已部署成功；既有独立灾备演练继续执行。该测试阻止并计数所有恢复类非 GET 请求，必须为零，不覆盖实际整站数据或触发付费服务。QA 账号通过正式删除接口清理；自动 Trace、录像和截图关闭，仅保存六张明确安全的截图。测试加入完整栈 CI，最终证据见整改记录。

无新依赖、数据库迁移或服务配置。升级保留前端镜像、配置和匹配快照；本地验收先停全部写入者导出 SQL，保留旧容器后切换前端。回退可切回保留前端，涉及其他批次数据库变化时仍需按对应文档恢复匹配点，不能只恢复旧 SQL。
