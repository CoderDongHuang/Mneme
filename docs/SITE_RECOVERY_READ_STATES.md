# 整站恢复：读取、归档校验与接受回执

对应原审查 P3-03、P2-14，沿用 P3-02/P3-04 的共享状态、日期、大小和反馈组件。只拆整站执行器页面的数据边界；不改备份格式、执行器权限、恢复算法或既有 API，不将完整恢复演练或整份审查提前标记完成。

## 行为

首次读取、空历史与失败分开。历史串行轮询并合并手动刷新；刷新失败保留缓存，明确提示可能过期，同时暂停备份、校验和恢复。读取未成功、正在读取或有 queued/running 任务时不能提交。数组、可渲染字段和报告指标先校验，错误响应显示可重试失败，不导致渲染崩溃。后台状态与恢复阶段使用共享 formatter。

归档校验使用独立 AbortController 和最新请求身份。切换归档清除原校验，取消旧请求；即使旧请求忽略取消后迟到，也不能覆盖新选择。重新校验时先撤销原成功，失败不能保留“通过”。历史中的归档消失或大小改变同样撤销校验。恢复只提交当前选择的已验证摘要；宿主机仍在接收和执行前重新核对内容哈希，防止同名、同大小归档内容变化。

每个凭证对应独立挂载作用域。锁定或更换凭证会清空归档选择、预览、历史、对话框和回执，取消历史、校验、提交的客户端等待；迟到响应不能进入新作用域。历史 401/403 清空旧数据与校验。凭证只在内存，不进入 localStorage/sessionStorage。

提交在业务 hook 内以同步锁防重复，并在确认时重新检查历史和当前归档，已打开的危险确认框不能绕过后来发生的失败。接受响应必须是匹配当前操作的有效任务，显示“已接受”而非完成；后续刷新失败不覆盖回执。该任务出现在历史前阻止重复提交，之后仍按 queued/running 状态阻止并发任务。提交异常表示结果未确认，不自动重发；先成功刷新历史核实后才重新允许人工操作。客户端取消不能撤销已发给宿主机的任务，刷新或重新解锁后必须检查真实历史。

## 验收与边界

单元回归覆盖首次失败与重试、非法响应、串行刷新、缓存过期、归档竞态、失败撤销原成功、归档变更、已打开确认框、重复提交、接受后读取失败、未确认提交和权限撤销。全量前端测试、Lint、生产构建和原包大小门禁必须通过。

site-recovery-states-real.spec.js 在实际 localhost 桌面与手机注册隔离账号，真实验证普通用户和错误管理员凭证的 403，并检查管理员实际 GET。未配置宿主机执行器时必须显示真实 400 错误，不能伪装空历史。随后浏览器历史 GET 和只读归档校验 POST 使用明确夹具验证故障、过期、响应归属与锁定；没有调用真实归档校验或创建整站任务，不宣称已完成生产恢复演练。测试阻止所有未明确夹具化的恢复类非 GET 请求，必须计数为零。QA 账号通过正式删除接口清理，凭证和自动 Trace/录像均不落盘；仅保存明确安全的视口截图。测试加入完整栈 CI；最终本地证据和 PR 结果记入整改记录。

无新依赖、配置或数据库迁移。部署保留前端镜像、配置与匹配的停写快照；本地先停全部应用写入者导出 SQL，保留旧容器再切换前端。仅本项前端可切回保留镜像；跨其他批次变更回退必须按相应文档恢复匹配点，不能只恢复旧 SQL。
