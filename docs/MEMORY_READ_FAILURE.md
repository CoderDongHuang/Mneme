# 长期记忆读取故障与安全重试

**状态（2026-11-04）：独立 PR [#101](https://github.com/CoderDongHuang/Mneme/pull/101) 全部 9 项 CI 通过并已合并。** 恢复后 Python 全套 1035 项、Java 全套 236 项（均无跳过）、Ruff、前端测试和生产构建通过；真实 localhost 桌面、手机故障与恢复回归共 2 项通过。

## 行为

按类别读取长期记忆或枚举维护用户时，存储异常抛出 `MemoryReadUnavailable`，不能返回空列表。真实空数据仍返回空列表。失败的读取不会发布到分类缓存；恢复后重新读取存储。

薄弱点合并和学习进度替换依赖旧记录。读取失败必须在修改重要性、添加或删除记录之前终止。FastAPI 返回 HTTP 503、固定 `MEMORY_READ_UNAVAILABLE` 及安全提示；Gateway 的记忆接口保留 HTTP 503，不透传供应商响应正文。前端沿用现有反馈组件，保存失败保留模态框及输入内容，供恢复后手动重试。

维护用户枚举失败向上抛出，由现有维护工作器的失败处理记录失败；不得返回“没有用户”的成功结果。日志仅记录异常类型和已有哈希标识，不记录底层异常正文。

## 验证

- `python-agent/tests/test_memory_read_failure.py`：分类缓存、合法空数据、读写 HTTP、无副作用、维护枚举和敏感正文隔离；结合缓存/删除围栏测试运行。
- `MemoryServiceTest`：通过实际 RestTemplate 响应解析与 MVC 异常处理，分别验证读取、写入的 503 及固定提示。
- `MemoryPage.test.jsx`：写入失败保留草稿；内容输入框使用稳定的可访问名称，输入后仍可由同一名称定位。
- `frontend/e2e/memory-read-real.spec.js`：真实 localhost 应用、注册独立 QA 用户、实际 Qdrant 旧记录及版本快照。对该用户的分类读取显式注入异常，不替换 HTTP 请求或页面响应；检查 503、旧内容/元数据/版本完全不变、表单保留、恢复后重试与刷新。桌面和手机分别执行，日志不得包含异常正文 canary。

真实 E2E 仅在 `MNEME_REAL_E2E=true`、`MNEME_MEMORY_QA_FAULTS=true` 时运行，会短暂重启 Agent；应在隔离验收部署执行。夹具限定新 QA 用户，finally 校验并恢复原源码字节、删除夹具、重启 Agent，并经正常账号删除流程清理用户。它证明客户端面对分类读取异常的恢复行为，不冒充 Qdrant 服务器整体停机或供应商生产网络故障。

## 发布与边界

无依赖或数据库迁移。Agent 同时部署 `app/` 和 `main.py`，Gateway 同时更新服务错误映射。升级前停应用写入者，保存匹配 SQL、Redis、Agent 数据、镜像和容器配置；若回退，先停写并恢复匹配数据，再启动对应旧镜像。

本项消除分类读取及维护枚举的“异常当作空数据”。其他读取路径、读写竞争、跨存储事务、完整回答后后台记忆任务（P1-06 / MN-007）及留存治理（P2-12）分别验收，不因本项完成而关闭。
