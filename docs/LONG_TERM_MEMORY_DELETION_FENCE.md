# 长期记忆与版本的删除围栏

对应源码审查 P1-05 的跨存储清理、异常传播、独立读回，以及 MN-006 的迟到写入防复活。本项覆盖 Qdrant 长期记忆及 SQLite/MySQL 版本记录；短期/工作记忆、Redis 和内存缓存仍按后续独立项处理，不能据此关闭整个审查。

## 存储协议

复用持久 generation 用户锁及账号 tombstone。新增、编辑、恢复、冻结、重要性、主题和元数据更新在实际发布前检查账号状态；账号删除提交 tombstone 后，迟到写入与版本快照被拒绝。查找记忆的首次读取只用于发现所有者，锁内重新读取当前内容并检查所有者，避免并发操作用旧元数据覆盖新修改。

Embedding 调用在用户锁外完成，删除不等待供应商返回；返回后重新取得锁并检查账号状态，显式传入向量发布，不能在 Qdrant 内隐式重复调用供应商。纯元数据修改不重新计算向量。无法撤回已经发送给供应商的请求，也不承诺清除供应商侧数据。

更新、删除及历史恢复的“修改前版本”与存储更新位于同一用户锁范围，恢复先重新读取实际当前版本。恢复输入中的 id/content 不进入元数据；读取以真实文档和主键为准，避免元数据覆盖。Qdrant 和版本数据库不是跨库 ACID：版本已保存而 Qdrant 写入失败时可能多出一次有效的修改前快照；不自动重放非幂等业务，也不把这种情况当成已完成更新。

版本号的 MAX+INSERT 在 SQLite BEGIN IMMEDIATE 内分配。MySQL 命名锁在显式 commit 后释放；失败先 rollback 再释放，避免前一事务提交前下一实例计算相同版本号。公开快照与版本删除同样使用用户锁，内部快照仅供已持锁的存储操作调用，避免嵌套锁。

账号删除后不再创建删除快照；普通单条删除/清空不写账号 tombstone，仍保留可恢复版本，允许后续正常新增。Qdrant 删除后独立读回主键/用户数量，版本删除后独立 COUNT；读错和静默删除残留必须传播，供原后台任务重试，不能把异常当零。

## 验收

单元测试用真实本地 Qdrant 和 SQLite，暂停供应商结果验证新增、更新、恢复期间账号删除不会复活；覆盖写入中删除等待、并发字段保留、恢复前最新快照、32 个并发版本、删除静默残留、计数错误、恢复重试和另一用户隔离。MySQL 合约测试明确检查 commit/rollback 与 RELEASE_LOCK 顺序。

`python scripts/check_memory_deletion_fence.py selftest` 在实际部署中使用当前配置的 Qdrant 与 Embedding，分别以 SQLite 和 `AUXILIARY_STORE_BACKEND=mysql` 执行。只在独立脚本进程暂停已返回的供应商结果，服务源码与服务进程不打补丁。合成身份有明确 QA 前缀，finally 清除向量、版本与合成 manifest；不切换离线向量污染现有索引。

`memory-fence-real.spec.js` 在实际 localhost 桌面与手机注册三个隔离账号，写入真实长期记忆，运行迟到新增/恢复与并发版本，检查第三账号的页面、实际内容和全部 35 份版本仍完整。最后通过正式 DELETE 接口删除账号，等待持久 tombstone 及两存储零残留，再以新进程重放迟到修改核对。既有记忆编辑/历史恢复、会话清理及 Trace/隐私围栏一起回归。没有使用虚构响应替代本项存储结果；自动 trace/录像关闭，仅保存安全视口截图。脚本双存储和真实页面回归加入完整栈 CI。最终结果及独立读回见整改记录。

## 部署与回退

无新依赖、配置或迁移。SQLite 使用同一主机的共享文件；多副本必须全部采用共享 MySQL 用户锁及版本库，并使用一致的 Embedding profile，不能混用不共享的 SQLite 围栏。索引 profile 不匹配仍拒绝写入，不自动修改非空索引。

升级先停全部应用写入者，保存匹配 SQL 和 Agent 数据快照，保留旧镜像/容器及配置，然后切换 Agent。必须停止旧消费者，避免旧代码绕过围栏。回退同样先停全部写入者；跨批次恢复必须使用匹配的数据库、Agent 数据及镜像，不能仅恢复旧 SQL 或让旧工作器继续处理已删除账号。持久 tombstone 不能随意删掉。本项仅保证逻辑清理与拒绝迟到发布，不承诺 SQLite WAL、磁盘空闲页或历史备份的物理不可恢复清除；这些留存策略属于 P2-12。
