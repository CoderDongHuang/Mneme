# 记忆与反思可靠性

记录输入快照、投递、租约及隐私边界。完整回答后的记忆处理由 Gateway SQL outbox 调度，回答状态与任务状态独立。已合并的读取修复另见 [读取故障](MEMORY_READ_FAILURE.md)。

<a id="durable-memory-completion"></a>

## 完整回答后的持久记忆任务

Gateway 将已核验回答、引用与 `memory_completion` 任务在同一事务提交，之后才向浏览器发送 queued 和 done。事务失败不能宣称回答保存成功；提交后的后台故障、断连或重启不把回答改为 failed。用户停止、客户端断开、模型超时和引用核验仍属于回答阶段，保留各自状态。

任务载荷保存 user/session/delivery、固定 reference_time、模型调用前冻结的 history 和最终 answer，不保存模型密钥。Gateway 从本用户 active 会话的已完成消息提供上下文，排除未完成轮次；最多 40 条、单条最多 4000 Unicode 码点、序列化总量不超过 24 KiB，原 SQL 正文不截断。Agent 加上本轮消息后最多 41 条。浏览器不能提交内部 history，也不能看到内部 completion 事件或载荷。普通聊天请求仍为 64 KiB，内部完成端点上限 8 MiB。

工作器按 owner/lease/fence 领取有限重试任务，网络调用前后分别核验账号、会话、完成回答及投递归属，锁外调用 `/api/v1/chat/memory/complete`。每次解析用户当前的加密模型配置，经内部请求头传递。Agent 在账号 SQL 状态保存输入指纹与分阶段检查点：历史、提取、逐条计划/应用、反思交接、摘要。供应商和 embedding 调用在账号事务外；并行提取只采用首个已提交结果。损坏检查点或相同投递的输入冲突明确失败。

高置信度效果使用稳定 effect ID；更新以原始分类快照作 CAS，薄弱点重要性保存绝对目标值，进度拒绝覆盖更新的轮次。Qdrant 点与 effect receipt 同次 upsert；版本快照保留旧 receipt。丢失确认后可从当前点或历史版本核验，后续用户编辑/删除不会被旧重试覆盖。淘汰项也只按原快照删除；超过版本证据保留期且仍未确认的计划拒绝重放，不猜测成功。低置信候选使用稳定编号。

Agent 成功回执经 Gateway 校验后，候选入库、清空载荷和任务完成同事务提交。失败保留载荷，任务中心提供专属重试；不会重新生成回答。旧 `memory_candidates` 任务继续可消费。账号/会话删除先写永久围栏，移除检查点与任务，迟到工作器不能恢复已删除内容。

检查点、活跃回执与失败载荷的容量治理归 P2-12。会话 manifest 计数的 30 天保留及 SQL 历史正文到期规则继续有效；这是有留存边界的恢复协议，不承诺跨不匹配备份永久 exactly-once。

无新增依赖或数据库结构迁移。升级需停止全部写入者、等待在途回答结束，保留匹配 SQL、Agent 数据、Redis、Qdrant、镜像和配置，再同时替换 Agent/Gateway/前端。禁止旧新写入者混跑。回退前先处理新增类型的任务；不能处理时停写恢复匹配全组快照，不能只降级镜像或删除载荷绕过恢复。

历史逐次日志已清理；已合并批次的测试与评审记录见 [整改索引](CODE_REVIEW_REMEDIATION_20261031.md)。下述为稳定行为约束；本次完整后台任务的验收证据记录于原清单及独立 PR。

## 蒸馏结果校验

对应 P1-06 / MN-007 的安全重试前提。模型必须返回 JSON 数组，每条包含 category、非空 content、有限且位于 [0, 1] 的数字 confidence，以及布尔 is_new；只允许额外的字符串 topic，weak_point 的 topic 必须非空。不接受字符串置信度、布尔置信度、重复字段、未知类别、供应商伪造来源字段、Markdown 包裹或部分合法的混合批次。先验证整批，再按 confidence >= 0.6 且 is_new=true 过滤，最后由本机生成来源与证据摘要。

合法空数组、全部低置信度或非新信息仍是正常无变更。非法结果抛固定消息的 DistillationResultError，日志只保留操作、结果和身份摘要，异常及 Trace 不包含供应商正文或原 JSON 解析异常链。失败不会返回空成功，也不会先应用批次中的合法前缀。供应商恢复后，后台任务重新提取持久载荷中的同一输入快照。

不增加立即网络重试；失败由持久任务的有限重试策略处理，已保存回答保持完成。升级和回退遵守上文的匹配快照协议；回退到校验修复前的镜像会恢复“非法 JSON 被当作空结果”的旧行为。

测试覆盖非法格式、字段和数值边界、深层 JSON、重复字段、整批拒绝、同输入快照恢复及异常正文隔离。真实 localhost 回归在专用账号后台任务中注入一次供应商无效输出，核验实际提取失败后恢复；继续检查候选入库失败不覆盖已保存回答、服务重启、手动重试、确认与刷新。

## 记忆蒸馏输入快照与候选编号

对应 2026-10-30 源码审查 P1-06 / MN-007。冻结输入与候选编号现已接入上述完整后台任务。

### 行为

prepare_conversation 在加入本轮用户消息后、执行模型前，将消息内容、时间和本轮 request_id 复制到内存状态 memory_input。未提供请求编号的内部调用生成独立 UUID。完成时蒸馏使用该副本，不重新读取会被后续请求修改的会话缓存；空快照也不能退回实时缓存。空闲间隔以本轮开始时间计算，模型耗时不能被当作用户离开会话的时间。

待确认候选的编号由用户、会话、本轮请求和规范化候选字段共同计算，同一候选在同轮重排或重复应用时编号不变；不同用户、会话和请求互相隔离。使用 SHA-256 的前 224 位加 pending_ 前缀，总长 64，兼容既有 pending_memory.memory_id。没有快照的旧内部调用继续生成独立随机编号。

冻结输入随回答同事务进入 SQL 任务载荷。高置信度效果、反思计数与进度更新另外依靠检查点和各存储回执去重，不能仅依赖候选编号。

### 升级和回退

无新增迁移。升级前停止接收新回答，等在途请求结束，停止写入并保存匹配数据、镜像及配置；同时部署 Agent、Gateway 与前端，再检查健康和实际会话。

回退需先结束在途请求，避免同轮在新旧编号算法间切换；已经提交的候选沿用数据库中的编号。现存 memory_candidates 任务继续遵守[候选持久化任务](MEMORY_RELIABILITY.md#pending-memory-outbox)的升级/回退规则，不能删载荷绕过恢复。含环境变量及数据库内容的本机 artifacts 仅作私有验收证据，不能提交。

<a id="reflection-delivery-idempotency"></a>

## 反思计数的持久投递回执

对应 P1-06 / MN-007 的反思计数去重，现由完整后台任务按固定投递身份调用。

### 身份与交接协议

`prepare_conversation` 在模型调用前固定 `delivery_id`。完成阶段按用户、会话及该 ID 记录一次反思计数，不依赖回答正文、时间或工作器身份。Gateway 请求已有稳定 request_id；没有 request_id 的直接调用，在 prepare 中生成随机 ID 并保存在持久任务输入中。同一个没有请求 ID 的新 HTTP 请求无法识别为旧请求，不能承诺跨请求去重。

复用 `knowledge_index_state` 的短用户事务：先检查账号、会话永久删除围栏，再验证并查询 `reflection_deliveries` 账本。账本使用会话 SHA-256 分桶，投递键为规范 JSON `[session_id, delivery_id]` 的 SHA-256，不保存正文或原始会话/请求 ID。结构损坏明确失败，不当空账本继续计数。已存在 SQL 回执只读取当前 Redis 计数；计数已消费时返回零，不重建计数。

新投递先由 Redis Lua 原子递增并写交接标记，再提交 SQL 回执，成功提交后才删除 Redis 标记。交接标记不设 TTL，旧版尚未过期的标记在重试时执行 PERSIST；因此 SQL 回滚、计数已消费或跨进程重放不会因标记七天到期而重新递增。计数自身仍默认保留七天，修复旧无 TTL 计数，重试不延长已有期限。SQL 已提交后的标记 DEL 故障仅记录固定诊断，保留已成功回执；后续重放或账号删除可重试清理。

没有两种身份的兼容调用仍将每次调用计为不同事件；只传一半身份在访问存储前拒绝。SQL 事务只覆盖短同步存储操作，不跨模型调用或 await。SQL 或 Redis 失败不回退本地，也不报告尚未提交的回执成功。SQLite 用于单主机；多副本需共享 MySQL 和 Redis，使用一致状态库配置。

### 删除与留存

回执保留到会话或账号删除，不能在后台任务仍可能重试时按七天清除。单会话删除在同一 SQL 事务写永久 tombstone 并移除对应回执桶；即使账本外层损坏，仍先提交 tombstone 再报告清理错误。账号删除先提交永久 tombstone 并删除全部回执，再执行可失败、可重试的 Redis/Stream 清理，已删范围拒绝迟到投递。另一用户和另一会话不受影响。

升级前已经过期的 Redis 标记没有可追溯的 SQL 回执，不能重建历史去重记录。SQL 未提交且不再重试的交接标记可能持续保留，账号删除会按精确用户范围清理；自动孤儿留存治理仍归 P2-12 后续验收。本项不声称 SQL 与 Redis 为 ACID，不将 AOF everysec 的断电 RPO 承诺为零丢失，也不承诺回退不匹配数据库后的去重。

### 升级和回退

无新依赖、配置项或数据库结构迁移，但用户状态增加持久回执协议。停止全部旧应用写入者，保存匹配 SQL、Agent 数据、Redis AOF/RDB、镜像和配置后再替换，不能混跑不认识回执的旧工作器。回退必须先停写并恢复上述匹配快照，再启动匹配旧镜像；仅回退镜像可能重复计数。任务所有权规则仍见 [反思队列协议](MEMORY_RELIABILITY.md#reflection-task-ownership)。上述子协议现由完整后台任务组合使用；长期容量治理仍归 P2-12。最终测试、实际截图和独立 PR 结果见 [整改记录](CODE_REVIEW_REMEDIATION_20261031.md)。

## 反思结果校验与可恢复失败

对应审查 P1-06 / MN-007 和 P2-01。此前 `run_reflection` 对非法 JSON 返回空对象，队列因未抛错而确认任务并扣减计数。现在区分“没有记忆可分析”和“供应商返回无效结果”：前者仍正常跳过，后者抛出固定消息的 `ReflectionResultError`，不携带供应商原文或原 JSON 解析异常上下文。

实际聊天回归在隔离 QA 请求中运行实际反思解析器和即时建议降级，继续验证回答保留、候选故障、重启、重试、向量确认及刷新，并检查日志与 Trace 不含私密标记。真实页面、完整测试及独立读回结果见 [整改记录](CODE_REVIEW_REMEDIATION_20261031.md)。

<a id="reflection-task-ownership"></a>

## 反思队列的任务身份与执行所有权

对应审查 P1-06/MN-007 的后台任务可靠性，以及 P2-01 的唯一 owner、续约与过期接管原则。反思队列与完整回答后的 SQL 任务分别保留执行所有权。

### 协议

排队使用 Redis Lua 原子读取计数、写入 Stream 和建立用户任务预约。预约独立于会过期的执行租约，失败或等待接管时不会再次创建同一用户的任务。任务携带稳定 job_token，每次实际执行另生成全新 owner；工作器不能读取并复用其他执行者的 owner。

执行租约最低 60 秒，每三分之一周期用 job_token 与 owner 比较续约。续约失败后拒绝完成；最终 Lua 再次核对两种身份，在同一操作中 ACK、扣除本任务计数、清理预约和租约并删除完成的 Stream 记录。失去租约、重复投递或重复完成不能扣减计数或 ACK 新执行者的任务。任务执行期间新增的会话保留，计数剩余值保留原 TTL。接管分页沿用 XAUTOCLAIM 游标，避免前面的活任务长期挡住后面的失效任务。

模型已发出的调用不能被 Redis 续约自动撤销；暂停进程恢复后可能与新执行者短暂并行，但旧执行者无法提交。当前 run_reflection 只读取长期记忆并返回分析结果，不写入长期记忆。如果后续增加持久化副作用，必须另行把 fencing 延伸至该存储，不能直接依赖这个租约。

### 升级与回退

此协议不支持旧新工作器混跑。升级前停止所有 Gateway/Agent 写入者，备份匹配数据库、Redis 完整持久化目录、数据卷、镜像及配置，再部署所有新 Agent。不能只停本机而保留其他实例。

旧 Stream 条目没有 job_token。旧租约到期后，新工作器根据当前累计计数原子建立一个新协议任务，合并同用户旧条目并 ACK/删除旧记录；存在活动旧租约时保留待接管，不抢执行。整个过程中计数不预先清零。迁移失败保持重试，不能通过删除 Stream、消费组或计数键“修复”。

回退同样停全部工作器，恢复匹配的 Redis/数据库/数据与镜像配置；旧版不了解新预约键和新身份协议，禁止只替换二进制后继续消费当前队列。AOF everysec 的 RPO 边界仍适用。


<a id="pending-memory-outbox"></a>

## 候选记忆持久化任务

对应 2026-10-30 审查 P1-06 / MN-007 的 Gateway 候选入库部分。以下保留 `memory_candidates` 旧任务兼容规则；新回答使用完整 `memory_completion` 协议。

### 回答与候选的提交边界

Gateway 在同一 MySQL 事务中，将带执行代的回答从 processing 更新为 completed，并将候选列表写入 processing_task 的 memory_candidates 任务。交接失败时整个事务回滚，不向浏览器发送 done 或 queued。没有候选时不创建空任务。

提交后同步响应返回 memory_status=queued、空 pending_memories；SSE 发送 pending 为空、status=queued 的 memory 事件，再发送 done。未入库候选不会暴露确认按钮。提交后的浏览器断开不能将回答改回 failed。

后台工作器沿用 owner/lease/fence 和有限重试，在单一受租约保护的 SQL 事务中校验账号 active、回答 completed 和归属，写入全部候选、清空任务 payload 并完成任务。任何一步失败均回滚；重试不修改已经确认/忽略的同源候选，不接受其他用户或其他回答的 ID 冲突。错误提示、通知和日志不回传候选正文或数据库异常细节。

失去租约的工作器不能继续写入。账号删除状态取消候选写入并清空载荷；会话删除移除对应任务，迟到工作器不能复活任务。删除前已经提交的候选保留既有来源外键 SET NULL 行为。任务页标明“来源回答”，提供保存失败的独立重试，不使用文档解析修复指引，也不能因数字 ID 相同修改无关文档。

### 升级和回退

没有新增数据库迁移，复用 processing_task。升级前保留匹配数据库快照、镜像和部署配置；本机使用忽略目录 artifacts 保存 SQL 和原容器，不能提交其中的私密环境文件。

先停止接受新回答并等待在途请求结束，再停写和备份，升级 Gateway 与前端后检查健康及真实任务。回退前先用新工作器处理完 memory_candidates 的 pending/retry/processing 任务；failed 必须处理或明确保留在匹配快照中。旧工作器不认识新增类型，不能直接对仍有未处理候选任务的数据库启动旧 Gateway。需要立即回退时，停写后恢复对应版本的数据库及原镜像/配置，使用成对备份，不能只换镜像。不得为让旧工作器启动而直接删除未保存的候选载荷。

成功和取消后 payload 清空；失败载荷为恢复保留。历史任务和其他存储的统一保留清理仍属于 P2-12。


<a id="session-redis-log-privacy"></a>

## Redis 会话诊断隐私

对应审查 P1-04 / MN-004 的元数据日志和异常泄漏验收。本项只覆盖 `session_persistence.py` 的连接、保存、恢复、删除和残留读回；不关闭短期/工作记忆的并发和迟到写入边界。

连接成功不打印服务地址；异常只记录固定操作、结果、异常类型和已有 trace_id。保存、恢复和删除按现有 `memory_log_fields` 记录会话 SHA256 截断摘要，不输出原会话标识、消息正文、Redis 返回值或异常文本。残留计数只记录批次大小。删除和读回仍抛固定 RuntimeError，抑制原始异常链，避免上层 `logger.exception` 或标准 traceback 再次输出 Redis/Pydantic 可能携带的正文。

Redis 故障标记镜像不可用；当前版本已按下述 SQL 历史协议保存正文和回执，SQL 提交失败必须向上传播。已迁移历史从 SQL 读取；尚未迁移且有版本或旧清单归属的历史在 Redis 不可读时明确失败，不作为空历史覆盖。删除和读回保持严格失败，原删除任务可以在服务恢复后重试，不能误报删除成功。

### 验收

单元测试分别注入连接、保存、恢复、Pydantic 畸形字段、删除和读回异常，用唯一标记检查 JSON 日志、直接格式化 traceback 和上层异常 logger；确认 trace_id 和会话哈希仍能关联，且清理失败后的显式重试可完成。保留原删除残留/静默失败测试。

真实 localhost `memory-outbox-real.spec.js` 在隔离账号的正式请求中运行实际六类错误处理，只替换独立临时持久化对象的 Redis 客户端，不中断共享 Redis、不向 Redis 存放标记。临时对象作用域、供应商输出和候选写故障夹具均按测试清理恢复。实际 Gateway 重启、回答保留、候选重试、确认向量与刷新继续回归；读取两服务 stdout/stderr、实际 Trace 和文本测试产物确认动态唯一标记没有泄漏。自动录像和 Trace 关闭，只保存安全视口截图。该故障夹具不代表对生产 Redis 进行了真实网络中断。

### 升级和回退

该诊断隐私子项本身没有依赖、配置、迁移或存储协议变化；当前版本另有下述 SQL 历史协议，部署时须一并遵循其升级与回退要求。升级仍停止全部应用写入者，保留匹配 SQL/Agent 数据、旧镜像和容器配置，再替换镜像；回退使用匹配数据和镜像。回退旧代码会重新暴露异常文本，不能据此宣称旧版本也具备本项保护。

本项不修改通用 JsonFormatter 的任意第三方日志策略，不保证异常对象在进程内物理擦除，不取消已发请求，也不宣称全部日志与整份审查完成。最终结果见整改记录。


<a id="session-message-delivery"></a>

## 会话元数据消息计数投递协议

对应 P1-06 的一个重放前置条件。prepare 在副作用前固定 request_id 或随机 delivery_id，用户注册计数、完成计数和反思共用该身份；prepare 冻结的 memory_input 随完整任务持久化，旧的直接 complete_conversation 调用已删除。无 request_id 的新 HTTP 请求仍无法识别为重放。

SessionStore 按账号、会话、角色去重，message_deliveries 仅保存规范 JSON [role, delivery_id] 的 SHA-256 键和 true。计数与回执同一次临时文件 fsync、原子 replace；SQL 用户锁和实例锁覆盖整个读取修改发布，不跨模型调用。丢失确认后重放或新实例不重复计数，也不改变标题和时间。API 列表不暴露回执，原始请求 ID 不写入 manifest。非法 ID 和损坏回执明确失败，不能当作空账本覆盖。账号/会话删除围栏优先检查，旧回执不能绕过删除保护。

去重仅覆盖仍保留的会话 manifest：现有 30 天 last_updated 过期清理会一起移除回执，重复调用不延长留存。删除也清除对应元数据；不是永久 exactly-once 协议。SQLite 为单机，MySQL 只提供共享锁，多副本仍需共享同一文件系统；SQL 锁不复制文件。短期历史另有下述 SQL 消息投递协议；完整后台任务按上文保留边界重放。

无新依赖、配置或 SQL 迁移，但增加了 JSON 回执协议。升级应停止全部旧应用写入者，保留匹配 SQL、Agent 文件、Redis 和镜像配置后替换。旧写入者不认识回执，不可混跑；回退使用匹配数据快照和镜像，不能只替换旧代码并承诺已有去重仍成立。

验收包括真实 SQLite/MySQL 的两个实例并发及新实例重放、序列化/fsync/replace 故障及丢失确认、损坏回执、隔离与删除；真实网页回归另在实际 Agent 中用新解释器读取原 manifest 并重放同一请求。完整后台任务按上文执行有限重试。

<a id="session-history-delivery"></a>

## SQL 会话历史与消息投递回执

对应 P1-06/MN-007 的重试前置条件。复用当前辅助后端的 knowledge_index_state：账号短事务中同时发布 session_histories 的消息、回执和会话 revision。SQLite 只支持单机；MySQL 使用用户行锁，多个实例读取相同 SQL 历史。模型调用在事务外。工作记忆仅复制已读取的历史窗口；API 不再用过期的进程内工作记忆补空历史。

每个会话以 SHA-256 分桶，回执键为规范 JSON [role, delivery_id] 的 SHA-256，值为 [role, content] 的 SHA-256。相同角色与 ID 重放不追加、不刷新 TTL/revision，同 ID 不同内容明确拒绝；timestamp 不作为消息身份。摘要压缩保留回执，重放不会把已压缩的原消息放回。未传 delivery_id 的旧内部调用仍逐条追加相同内容，不猜测重复消息。

SQL 提交失败向上传播，下次读重新从 SQL 获取，不信任内存镜像。提交成功但确认丢失可按同一消息身份重放。Redis 仅为兼容镜像，写入失败不撤销 SQL 结果。未迁移的旧历史先按原归属和 revision 校验 Redis，再在账号事务内迁移；不可读或格式不符明确失败。新会话先持久历史再注册 manifest，避免 Redis 离线时把自己误判为旧会话。Redis 写后 SQL 回滚留下的不匹配镜像也拒绝导入，不能读取未提交正文。

沿用 SESSION_TTL_HOURS（默认 24 小时）的不活跃过期窗口。访问过期桶时惰性删除正文和回执、推进 revision 并留 expired 标记，阻止旧 Redis 或热缓存复活。下一次活动开始新去重窗口；本协议不是永久去重。无人访问的 SQL 正文与回执也由下述后台任务到期回收；长期活跃会话回执仍无容量回收，完整 P2-12 未完成。冻结输入及长期写入的重放依靠上文独立任务协议，不能仅由本消息回执推断。

账号删除直接清除整个 session_histories，包括没有 manifest 的孤儿桶。新 deletion-report 字段 sql_session_histories 原样统计所有桶，不按到期或删除状态隐藏残留；Gateway 要求该字段存在且为零，当前账号协议为 19 项。损坏状态明确失败且只返回固定错误，Pydantic 字段值和正文不会进入异常链。

### 无访问过期回收

Agent 启动时注册 SQL-only 的 `session_history_retention`，每分钟按用户主键分页扫描最多 100 个账号，包括仅有 SQL 历史、没有 manifest 或向量数据的账号。每个账号独立取得既有 SQL 事务锁，在锁内重新读取并严格校验历史；删除到期正文和回执、推进 revision、保留 expired 标记及永久删除围栏。扫描后产生的新消息续期不会被旧快照覆盖，多个 Agent 同时回收不会重复推进已过期桶。SQL-only 不表示进程中的 Redis/向量服务已经关闭，只表示此任务没有调用它们。

游标只在本进程内保存；到页尾开始新一轮，重启从头扫描。失败账号整笔回滚并在下轮重试，不阻塞后续账号；扫描失败保留游标。日志只记录计数、固定操作、异常类型和账号哈希，不附 SQL/JSON/历史异常正文。回收量只统计收到提交确认的事务，提交后丢失确认可安全重试。账号数、故障和重启均影响完成时间，因此不承诺固定全库清除时限。

这里保证 SQL 当前逻辑正文与回执到期清除、旧镜像不能重新导入；不保证 Redis 旧镜像提前于原 TTL 清除、进程中所有副本定时擦除或备份/WAL/介质不可恢复擦除。expired 标记与删除围栏继续保留；长期活跃回执容量、文档版本/对象/备份和孤儿文件治理仍待 P2-12 完整收口。

`test_session_retention.py` 覆盖分页、续期、并发、事务回滚/丢失确认及损坏账号隔离；`check_session_manifest_fence.py` 用独立 QA 身份验证实际 SQLite/MySQL。真实页面回归 `memory-outbox-real.spec.js` 只将本 QA 账号历史设为到期，不直接调用回收函数，等待运行中 Agent 的分钟调度，核对活动桶保留、永久回答仍可读和注销后 SQL 桶清零。

### 升级与回退

无新依赖、配置或 SQL 迁移，但 SQL state 现在包含私密对话正文，必须纳入备份访问控制、加密和留存范围。停止全部旧 Gateway/Agent 写入者，保留匹配的 SQL、Redis、Agent 数据、镜像和配置，再同时部署理解 19 项清理协议的新 Gateway 与 Agent。旧写入者不认识 SQL 历史和回执，禁止混跑；回退须停写并恢复整组匹配快照及镜像，不能只替换旧程序后沿用新状态。现有完整回退组保留在忽略目录，不提交数据或私密配置。

验收入口：test_session_history_delivery.py 覆盖实际 SQLite 并发、回滚、丢失确认、冲突、摘要、到期及删除；check_session_manifest_fence.py 在实际 SQLite/MySQL 配置上验证两实例并发及故障恢复；memory-outbox-real.spec.js 在 localhost 聊天流程后用新解释器、仅本进程 Redis 离线检查 SQL 历史重放，再正式注销并核对 SQL 桶清零。它不等于停止共享 Redis 或完成整个后台记忆生命周期。

<a id="completion-checkpoint-retention"></a>

## 完成任务检查点留存与容量

对应 P2-12。既有 SQL 分页回收任务也清理 `memory_completions`，不增加调度器。每个账号事务内先验证完整检查点清单，再移除到期任务和空会话桶；损坏账号整笔回滚，后续账号继续处理。默认 `MEMORY_COMPLETION_RETENTION_DAYS=30`、`MEMORY_COMPLETION_MAX_JOBS=1000`、`MEMORY_COMPLETION_MAX_BYTES=16777216`，三项必须为正整数；字节按规范 UTF-8 JSON 计算，只限制完成任务检查点，不代表整个账号的 SQL/文件/向量配额。

留存按冻结请求的 `reference_time` 计算，上限为 `MEMORY_VERSION_RETENTION_DAYS`（默认 180 天），避免重放时用户删除/编辑的版本证据已经丢失。实际删除后持久化账号截止时间，时钟回退或延长配置不能重新接纳已经退役的请求；超过当前时间五分钟的请求拒绝执行。缺少原请求时间的旧检查点保留并计入容量，不能从 `created_at` 猜测；只有冻结输入指纹完全匹配的重试才能补齐原时间。旧任务因此可能需要人工核查或删除不再需要的会话，不能直接丢弃其回执释放容量。

容量在阶段开始和发布结果时检查；不足时明确失败，不淘汰仍有效任务。模型、嵌入和摘要调用保持在账号事务外，提交历史、计数、反思和向量/摘要结果前在已有事务内重新检查时间围栏。调用期间到期的迟到结果不能重建检查点或写回旧任务；反思 Redis 投递标记在 SQL 回执提交后才清理。已保存的 Gateway 回答不因后台容量不足或检查点过期消失，可在任务中心查看失败。已经失效的任务不能通过重复点击重试恢复执行；需要重新发起当前对话请求。

这是有期限的重放保护，不是永久 exactly-once。长期活跃的短期历史、会话计数和反思投递回执尚未在本子项获得容量回收，旧版未知临时文件、远端对象执行和完整 WAL/孤儿治理仍归 P2-12，不能据此关闭主项。

验收入口：`test_completion_retention.py` 覆盖实际 SQL 并发、损坏清单、单调截止时间、数量/字节拒绝、旧输入匹配、调用期间过期及向量丢失确认后删除保护；`check_session_manifest_fence.py` 在实际 SQLite/MySQL 验证双实例回收。`memory-outbox-real.spec.js` 在 localhost 真实回答、后台故障、重启、重试及确认后等待运行中分钟调度，同时核对活动/旧格式检查点保留、过期任务拒绝重放、永久回答可读和正式注销清零。

没有新依赖或 SQL 迁移，但增加 SQL JSON 状态和三项配置。必须先停止全部旧 Agent 写入者再升级；旧写入者不理解截止时间和提交围栏，禁止混跑。回退须停写并恢复匹配的 SQL、Agent 数据、Redis、镜像及配置；只换旧镜像不能保证已有任务去重或防止退役请求复活。已有唯一完整回退组继续保留。
