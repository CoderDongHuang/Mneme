# 管理员基础设施业务诊断

对应审查 P3-07。运维页保留只读健康探针，另提供六个明确触发的业务检查按钮；刷新运维状态不发送邮件、不测试写入、不运行备份。`POST /api/v1/admin/operations/check/{component}` 同时要求有效登录、服务端管理员角色和独立管理员凭证。浏览器不能指定目标地址、收件人、命令、文件路径或密钥。

## 结果含义

`configuration` 表示配置存在与否，不证明凭证有效；`connection` 表示当前连接和认证；`operation` 表示实际合成业务操作；`cleanup` 表示操作后独立核验清理。各阶段分别展示，通过、失败、未执行和不适用不能互换。结果包含检查时间，网络响应丢失时清除旧成功状态并提示结果未知，不自动重放。锁定管理员页面会取消浏览器等待、清除结果与凭证；取消等待不能撤销已发出的服务器操作。

| 类型 | 真实操作与清理 |
|---|---|
| MySQL | 当前 Gateway 运行账号连接，使用 V33 专用表执行 UUID 行的 INSERT / SELECT / UPDATE / DELETE；finally 再删除并 COUNT 确认零。仅能 SELECT 的账号不能通过业务检查。 |
| Redis | 当前连接工厂使用配置的 AUTH，实际 PING；唯一测试键 NX 写入、读取和删除，finally 再 EXISTS 确认零。测试键有 60 秒 TTL，不使用用户键。 |
| Qdrant | Agent 对每个配置分片创建独立合成集合，写入、读取向量与 payload、检索、删除点及读回，finally 删除集合并确认不存在。保留用户集合。 |
| 对象存储 | 当前 S3 bucket 中独立 `.mneme-diagnostics/` 对象上传、下载比对、删除并 stat 确认 NoSuchKey；本地存储模式使用受控根目录临时文件，连接列显示不适用。 |
| 备份密钥 | 由受保护的主机执行器使用当前备份实现，验证 AES-GCM 加解密、HMAC 签名及篡改拒绝；KMS 模式另验证随机数据密钥 wrap / unwrap。既不读取业务数据，也不创建备份/恢复任务。 |
| SMTP | 从数据库读取当前 active 管理员已验证的邮箱，先检查真实 SMTP 连接，再发送固定测试邮件；Redis 跨实例每账号一分钟限制。SMTP 接收与邮箱最终收信分别判断，必须由收件人核实收件箱。 |

错误只返回固定代码，去除底层异常文本、密钥、命令行和供应商响应；Java 重新校验远端字段并丢弃未授权字段。Agent 检查端点仍受内部服务令牌保护，主机执行器仍受独立 bearer 令牌保护。主机检查与备份/恢复共用互斥锁，繁忙时返回 BUSY，不能同时操作。

Qdrant HTTP 检查复用当前端点与认证创建独立两秒超时客户端，不改变业务客户端；本地模式复用已打开客户端，不能重复打开同一路径。总业务时限 45 秒，随后仍尝试清理；未检查分片不计为通过。进程内互斥拒绝并行诊断。Gateway 独立诊断 HTTP 连接上限 3 秒、读取上限 75 秒；KMS wrap / unwrap 各有既有 30 秒进程上限；S3 使用独立受限客户端。浏览器断开或传输超时后仍应核实结果和残留资源。

## 配置、升级与回退

无需新增凭证配置，使用现有运行账号、SMTP、对象存储、内部令牌和主机恢复执行器配置。主机执行器缺失、凭证不完整或连接失败必须据实显示；未配置不是检查成功。该检查只验证当前备份密钥，不证明所有历史归档、历史版本密钥或整站恢复均可用，整站演练仍使用原有独立流程。

V33 仅新增合成诊断表，不读取业务表进行写权限探测。升级前停止所有应用写入者，保存匹配 SQL、Redis、Agent 数据、镜像及容器配置；升级 Agent、Gateway、前端，并重启主机执行器以加载新增检查路由。Gateway 迁移账号需要建表权限，运行账号需要诊断表 CRUD。不要为通过诊断提升运行账号至 root。

回退前同样停写，使用匹配版本和数据；不能把旧镜像直接覆盖到跨版本恢复后的数据库。合成资源通常在 finally 清理；强制结束进程、网络失联或存储拒绝删除时可能残留，仅按诊断专用前缀/表核实，禁止清空用户数据。长期孤立资源留存属于 P2-12 的独立验收，不以本项冒充完成。

## 验收方法

Java 测试使用真实 MySQL / Redis / S3 兼容服务及 SMTP TCP 服务，验证 AUTH、运行账号权限不足、读写和零残留；Python 测试覆盖真实双本地 Qdrant 分片、总时限、并发互斥、失败后清理、密钥篡改拒绝，以及真实主机 HTTP 鉴权和密钥检查无任务副作用。前端测试覆盖重复点击、旧结果替换、异常隐私、锁定后迟到响应。

`frontend/e2e/infrastructure-diagnostics-real.spec.js` 连接真实项目地址，在桌面和手机注册隔离账号，通过真实邮箱验证流程，再验证本人邮件实际到达 Mailpit、发送限流、权限和 SQL / Redis / Qdrant 清理读回；保留安全视口截图。未配置的备份执行器如实记录，不冒充密钥成功。最终运行证据与提交结果见源码整改记录。
