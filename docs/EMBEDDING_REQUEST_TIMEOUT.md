# 嵌入服务网络超时

在 P1-06 / MN-007 的真实记忆确认回归中发现两层等待问题。首先，DashScope SDK 仅将 `request_timeout` 作为网络超时，原 `timeout=10` 进入模型 parameters。改正后实测仍需一分钟：域名返回六个地址，requests 为每个地址分别等待十秒，且读取超时不能限制持续缓慢传输的总时间。两轮失败日志保留，不将第一层修复误当完整解决。

嵌入请求现使用已有 aiohttp 依赖访问同一 DashScope REST 接口，模型、输入、服务地址、代理环境和向量空间不变。asyncio.timeout 和 ClientTimeout 将多地址连接、等待响应和完整正文读取合并限制为十秒，拒绝重定向。失败仍保留原有索引并返回可重试错误，不写入本地哈希向量冒充在线向量，也不自动重试记忆确认写入。

Qdrant 的回调为同步接口；没有运行中事件循环时直接运行独立事件循环，异步接口调用时在一个自有线程运行并等待退出。请求超时主动取消 HTTP 后关闭会话、循环并加入线程，不能仅让 Future 等待超时后留下真实请求。当前同步回调仍会阻塞调用方至返回或超时，不把此项误称为整个 API 非阻塞改造。操作系统调度及底层 DNS 清理不构成硬实时保证。

`tests/test_embedding.py` 使用真实本地 HTTP 服务验证正常向量响应、延迟响应和持续缓慢正文的总超时；同步调用及异步接口调用分别覆盖，检查线程退出、请求正文不含两种超时参数，以及失败不切换向量空间。测试只用假凭据，禁止外网访问；超时用例使用正式十秒值，不缩短参数来绕过验证。

无数据库或接口迁移。部署前结束在途请求、停止写入并保留匹配数据库、Agent 镜像与配置；部署后检查健康和真实记忆确认。回退使用原 Agent 镜像与匹配配置；旧版本会重新暴露等待问题，不建议长期回退。完整 Python 记忆后台生命周期仍须独立完成，本修复不关闭整个 MN-007。
